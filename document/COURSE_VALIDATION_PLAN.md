# 课程与多 Agent 验证方案

日期：2026 年 10 月 2 日。

状态：产品验收设计，尚未实施；下列课程和检查项均未获得通过记录。本文细化 [课程支持矩阵](COURSE_SUPPORT.md)，不代替后续完整功能、性能和部署测试计划。

## 1 要验证什么

每门声明支持的课程都要测试。产品测试检查系统能否按声明范围开展可靠教学；学生学习核验检查某次表现；个人持续学习观察长期使用体验。三者分别记录，课程功能通过不等于已经证明学习效果。

| 验证工作 | 范围 | 记录与结论 |
|---|---|---|
| 公共能力测试 | 目标协商、本地记录、登录关联、同步、权限、任务版本、运行和恢复等 | 可以复用公共结果，但仍检查各课程实际接入是否正确 |
| 逐门课程验收 | CS01–CS13 各自的课程范围、主要教学活动、专用环境、核验、连续学习 | 每门课单独登记，按知识单元及活动类型报告实际覆盖 |
| 多 Agent 检查 | 教学角色分工、交接、工具事实、判断依据、失败与预算 | 公共协作案例加各课程特有案例，不以角色数量或彼此赞同判通过 |
| 个人持续学习 | 本人选择一门课，跨章节、跨会话、提示后独立表现及后续再检验 | 记录真实问题与表现；不替代其他课程验收或证明群体效果 |

开发可以先打通一门课的原型，然后逐门补齐。产品发布时，声明的常见课程范围必须对应验收记录；未覆盖内容明确标注，不以一个演示案例宣称整门课程通过。本人无需把所有课程完整重学一遍，课程内容与标准仍需安排审阅责任。

## 2 教材可选，教学依据需可检查

各课程都检查两种入口：仅有课程名称／学习意图，以及可选提供教材、大纲、讲义或课程链接。无资料入口使用产品经核对的默认知识范围、先修、活动与标准，先提出可修改目标，再展开教学。

参考资料帮助对齐范围、术语、符号和深度，提供可定位的出处；不是学生启动前必须完成的准备。默认教学依据同样要维护来源、版本与审核记录。生成草案可以继续讨论，未经核对的任务或标准不能获得可信通过标识。

测试可选资料的章节对齐、解析缺失、不同教材术语及不同任务条件；出现差异时保留目标和作品版本，说明调整理由。不能因没有指定教材而阻断学习，也不能把同一次模型生成的讲解、题目与答案互相当作可靠依据。

路线审阅核对声明范围内的重要主题与先修是否遗漏；活动验收按类型展开。一个活动通过只能支持该活动的结论。整门课持续体验另记实际完成范围，不能由结构审阅或代表性任务自动推定整门内容和学习效果已经验证。

## 4 多 Agent 教学检查

教学应能围绕当前目标提供解释、示例和实践，根据真实学生动作调整。以下检查使用预先审阅的条件与标准；测试用预设作品明确标为测试输入，不冒充本人真实学习成果。

1. 目标不明确或基础未知：规划与诊断提出可修改草案，不虚构兴趣、能力或替学生确认。
2. 学生卡住：辅导利用当前任务和帮助历史，提供适量解释；交接包含版本、作品、证据和待处理问题。
3. 任务与答案：实践任务和核验使用可检查标准，覆盖合理替代解法、反例与新条件；发现标准错误可纠正并保留历史。
4. 请求执行：工具返回真实事实，角色依据结果反馈；工具故障、超时或缺失证据保持待核验。
5. 角色意见冲突：说明不同依据和需要补充的验证，不能按投票更新为已掌握。
6. 查看完整答案：自学可自主查看，教师发布按开放条件；记录实际帮助，后续提供新任务，答案后完成不能升级成独立表现。
7. 返回与改目标：恢复作品、待完成动作和帮助，课程或资料变化不静默覆盖旧判断。
8. 权限与费用：所有角色遵守同一授权和调用预算；访客不建立长期云端学习档案，失败不无限互相调用。

普通请求可以只调用一个必要角色；需要协作的场景核对真实职责调用和交接。记录模型、提示与工作流版本、工具输入输出的适用范围、问题、等待和成本；私有内容按本地／账号规则保存，经整理的非个人验收结论才进入 Git。

### 4.1 答案策略验收

检查同一学生的自学与教师发布任务分别执行来源规则；关联教师不限制其他自学。教师随时、有效提交后、指定时间和手动开放分别验收，时间与提交条件不信客户端自述；策略允许但无可靠答案时显示待提供／待核对。

检查直接接口、客户端改来源、同步或平台复制关联实例、跨账号、检索、导出和附件不能绕过；受限答案不提前进入学生缓存或无权角色上下文。所有教学角色的示范、补全、评价和累计提示遵守策略，同时仍能提供允许范围内的概念解释及错误反馈。

检查教师修改规则后的旧页面和迟到结果按有效策略控制新分发；已经揭示的内容无法保证收回，历史策略、帮助与真实结果仍保留。开放后正确提交不自动成为独立表现，后续新条件任务独立取证；合理替代解法仍按标准核验。

### 4.2 Skill 生成、提供与组合验收

教师和学生分别创建／导入声明式 Skill，检验私人试用、主动分享、接收采用及课程发布权限；访客本地保存，登录承接，账号切换不改变所有者。分享方法不能连带公开私有材料、聊天、作品或受限答案。

检验复用已有方法、缺口自动生成草案、不同角色独立核验、正常与故意错误产物、替代解法和真实工具事实；草案生成、结构通过或角色同意不自动写成可信通过。按 CS01–CS13 实际活动验收 Skill，不能凭生成包数宣称课程已支持。

检验多 Skill 在不同阶段选择与组合、重复或冲突的处理、版本更新／停用、历史与恢复、调用预算和无权工具需求；恶意或错误包不能改角色、放开答案、读取其他资料或将既有失败自行变成可信通过。Skill 自带任意程序的执行不属于首版导入能力，学习任务中的程序、SQL、网络与数据实验仍按平台适配器验收。

### 4.3 理论与实践结合的体验验收

CS01–CS13 按适用活动分别验证以下规则，使用已核对的内容与实际学生／测试输入；本节不提前证明学习效果：

1. 单元围绕具体问题组织必要理论与学生尝试，实际结果可进入原理讨论、修改及新的应用；不以看完整章或讲解生成完成解锁实践。
2. 零基础可以先获得必要说明、直观模型或示范，再尝试；已有基础可以先探索。不强制先猜未知知识或先失败，主动查看答案仍按任务来源规则。
3. 正确、错误及证据不足的输入产生适当的不同支持，角色能指出当前版本、触发现象与对应原理。环境失败先处理故障，不据此诊断学生能力。
4. 操作成功但解释或适用条件不足时，不自动认定理解；单元有原理归纳与新条件应用，理论活动允许推演、反例和设计而非必须编码。
5. 学生可在同一活动持续编辑、运行、查阅理论和讨论，不在每次点击后审批或测评；退出后接续真实作品、结果和待完成动作，而不只恢复聊天。
6. 路线对照关键概念、先修、活动及证据，检查项目任务是否遗漏课程理论；学习卡住可补必要内容后返回原问题，核验放在有意义的阶段。

## 5 记录与回归

验收记录包含课程与知识单元、声明范围、活动类型、输入条件、预期规则、实际结果、课程／模型／工作流／工具版本、证据位置、复核人、日期和未覆盖项。分别报告公共能力、课程适配、协作与个人使用，当前不预填通过率。

课程内容、任务标准、模型、提示、工作流或执行环境改变后，重跑受影响案例；影响通用教学行为时，在全部声明课程上检查代表案例。可确定性核对的工具与同步案例可自动回归，开放教学质量与证明、设计等保留必要审阅，不用模型自评作为唯一发布标准。
