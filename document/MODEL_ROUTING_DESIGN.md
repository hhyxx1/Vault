# 开源版模型配置与职责路由

版本：v0.1，2026 年 10 月 6 日。关联正式需求 FR47。本文区分已经运行的部署级切片与仍需交付的个人配置。

## 产品行为

模型是可替换的推理资源，Agent 是受约束的教学职责。诊断、辅导、实践任务、核验解释及按需课程／Skill 设计可各自绑定不同 profile；一个 profile 也可复用。默认配置只建议模型，不强制 DeepSeek。学生或教师在有权限的模型中选择本次模型，切换前看见提供方和将发送的内容，切换后仅影响新请求。按职责的默认路由不能在错误时自动跨供应商重试；重试或换模型由用户决定。

开源版必须支持部署者共享配置、自托管端点和用户本人模型配置。个人配置不能让教师读取学生密钥，也不能让学生借用教师的私有凭据。未登录状态可使用当前实例明确开放的 profile；未来的访客个人密钥只保存在本设备的受保护设置中，不进入账号同步或学习证据。账号个人密钥需服务端加密存储、独立撤销和删除；目前尚未实现，不能在页面上假装已支持。

能力按文本、推理、视觉、结构化输出、工具使用分别声明与实测。当前 CS03 辅导只要求文本，模型生成 JSON 后仍由 Pydantic 验证；不把兼容接口宣称为全部能力兼容。模型不能写掌握状态、调用任意工具、越过资料可见性或答案策略。

## 已实施的部署级切片

后端保留 DeepSeek Responses 适配器，增加 OpenAI 兼容 Chat Completions 适配器。可信部署者通过 `VAULT_MODEL_PROFILES` 提供 profile 列表，用 `VAULT_MODEL_TASK_DEFAULTS` 绑定职责默认值；密钥只通过 profile 指定的环境变量读取，不出现在 profile JSON、公开列表或 OpenAPI。HTTP 仅允许回环本地端点，远端需 HTTPS。模型请求不携带工具定义、不跟随跳转，限时限并发，并对返回结构重新校验。公开列表只返回 id、名称、提供方和声明能力；学生单次请求传 profile id，幂等请求内容包含该 id。当前前端已显示模型选择和实际提供方，并在改模型／改职责后清除旧的发送同意。

例如，部署者可设置以下**无密钥**配置并自行保证模型服务可达：

```json
[
  {
    "id": "local_tutor",
    "label": "本地辅导模型",
    "provider": "本地",
    "protocol": "openai_chat",
    "base_url": "http://127.0.0.1:11434/v1/",
    "model": "your-installed-model",
    "capabilities": ["text"]
  }
]
```

部署时将此 JSON 作为 `VAULT_MODEL_PROFILES` 环境值。远端服务的 profile 可设置 `api_key_env` 为独立环境变量名，凭据放在该变量中；不得把真实密钥写入 JSON、Git 或文档。`VAULT_MODEL_TASK_DEFAULTS` 为如 `{"hint":"local_tutor","explain":"local_tutor"}` 的 JSON。`VAULT_AGENT_ENABLED=true` 时至少要有一个有效 profile 或已配置的旧 DeepSeek 凭据。此路径适合个人自托管或由实例管理者配置共享模型，**不是**多用户的个人 BYOK 管理。

## 待实施的个人配置与发布门

1. 学生和教师各自创建、测试、停用、删除连接；记录连接所有者、协议、允许的模型、能力测试结果、任务默认、配置版本和披露版本。本人可见自己的连接，教师课程不会自动获得学生的密钥。
2. 服务端用独立密钥加密账号凭据，密钥不随账号数据导出、同步或 Agent checkpoint；轮换、撤销、删除和备份恢复分别验证。访客若保存凭据，只保存在本设备并明确风险与清理入口。
3. 任意用户提供的远端 URL 先经过专用出口代理的 DNS／IP／重定向与网络范围控制，禁止内网元数据和业务服务访问；在此之前只接受部署者可信配置的 URL。连接测试使用最小无作品探针，不能为了探测能力泄露学生正文。
4. 记录每次真实使用的 profile 版本、请求模型与响应模型、职责、输入授权、token／费用来源和失败码。模型质量、成本、数据处理条款和课程任务适配以真实端点逐一测试；未获真实供应商凭据时不能声称这些通过。
5. 发布测试覆盖跨账号密钥隔离、教师私有资料／受控答案、撤权时模型调用、错误时无跨商转发、费用上限、模型停止服务与本地模型断线恢复。相关追踪见 [综合测试计划](TEST_PLAN.md)。

OpenAI 兼容接口的覆盖范围以具体实现为准；[vLLM 官方服务文档](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/)列出 Chat Completions 等接口，但并不保证任意模型都有相同能力。当前切片只使用共同文本接口并严格校验最终回复。
