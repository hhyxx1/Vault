# 原型与产品默认方案建议

日期：2026 年 10 月 2 日。

状态：基于已确认需求和官方资料提出的建议，尚未全部由项目发起人选定，尚未安装、部署或运行验收。本文把“待定”事项收敛成可以讨论与实现验证的基线，不把建议写成已实现结果。

本轮按用户要求优先收敛六项主选方案，见第 11 节。当前是供确定的具体建议，未将请求建议记成批准；选择后还需通过实现验收。

## 2 个人真实学习：首选数据结构

推荐本人持续学习数据结构。系统应能依据经核对的默认课程开展多 Agent 教学，教材与外部课程不作为前提。如本人希望有外部对照，可选 [浙江大学陈越、何钦铭《数据结构》](https://www.icourse163.org/course/ZJU-93001)，或高等教育出版社陈越等《数据结构》第 2 版，ISBN 9787040451108。[出版社教材信息](https://xuanshu.hep.com.cn/front/h5Mobile/bookDetails?bookId=59cf31acba9eb884cf821730)

选择理由是它同时包含概念、结构状态、算法分析、编码、调试和应用选型，能检查系统是否把讲解、尝试、证据和后续学习真正接起来。官方课程要求已有一门编程语言基础，示例偏 C；这不要求产品只支持 C。

这只确定个人持续使用的候选路径。所有声明支持的课程另行逐门检查课程范围、活动、环境、核验与继续学习，不能因本人只学习一门而免除验收。具体分工见 [课程与多 Agent 验证方案](COURSE_VALIDATION_PLAN.md)。

开始前用一个约半小时的小任务观察数组、函数、结构体、指针和递归等必要基础。局部薄弱先补相关活动，基础明显不足时先学 [浙江大学翁恺《程序设计入门——C语言》](https://www.icourse163.org/course/ZJU-199001)，随后衔接数据结构。起点检查不是强制考试或封锁学习入口。

建议目标：沿本人确认的课程范围持续学习，能解释常见结构的适用条件，独立实现并测试关键操作，说明复杂度和约束，在综合任务中作出并解释选型。先核对相邻单元的产品闭环，再继续整门课；不以视频完成率、刷题数量或证书替代实际表现。

每周 4–6 小时可作为个人安排的建议，实际按本人时间和进度调整，不承诺学习完成日期。保存提示前后作品、新条件下的尝试和之后的保持表现，按 [个人测试方案](SELF_STUDY_TEST_PLAN.md) 记录。

课程主页和出版社信息已核对；视频实际观看受外部平台账号、选课及课程开放条件影响，不承诺所有内容永久免费可看。产品保存链接、定位与自创活动，使用教材和外部内容需核对授权，不搬运整套资料。[平台帮助](https://www.icourse163.org/help/help.htm)、[平台服务协议](https://www.icourse163.org/topics/mooc_privacy_service)

## 3 语言环境建议

以下只确定推荐分支与标准；安装时锁定可复现工具链，补丁升级先通过对应案例，再更新环境版本。旧尝试保留当时版本。

| 环境 | 建议基线 | 课程行为与依据 |
|---|---|---|
| C | GCC 15.3，显式 C17 | 编译参数固定，不依赖编译器默认方言。[GCC 发布](https://gcc.gnu.org/releases.html) |
| C++ | G++ 15.3，默认 C++17；活动需要时用 C++20 | 标准逐活动声明，新特性先验收，不宣称全部标准特性已覆盖。[GCC 标准支持](https://gcc.gnu.org/onlinedocs/gcc-15.3.0/gcc/Standards.html) |
| Java | Eclipse Temurin JDK 21 LTS | 采用已核验的维护补丁，不开预览特性，固定编译目标。[官方支持](https://adoptium.net/support/) |
| Python | CPython 3.14.x | 通用编程以标准库为基础；当前为 bugfix 分支。[官方版本状态](https://devguide.python.org/versions/) |
| JavaScript | Node.js 24.x LTS | 明确服务端脚本与模块规则，浏览器 DOM 活动另适配。[官方发布表](https://nodejs.org/en/about/previous-releases) |
| SQL | PostgreSQL 17.x | 当前官方列出 17.11，后续跟进维护补丁；学生数据库与业务库分开。[版本政策](https://www.postgresql.org/support/versioning/) |

AI／ML 建立独立的 CPU 小实验环境，锁定数据、划分、NumPy 等实际所需依赖和预处理版本，先验证小任务能重新执行。首选与通用 Python 同分支；依赖确实不兼容时可建立 Python 3.13 兼容环境，并维护安全更新。不能因为基础 Python 可执行就把全部数据实验标成可用。

实现时记录工具准确版本、标准与参数、库与系统依赖、架构、环境标识和资源配置。若采用 Piston 或 Judge0，则先核对该实例实际运行时目录，再跑验收；不能把上述建议直接写成其现成支持清单。

## 4 执行服务建议

推荐平台自己管理权限、任务和证据，以薄适配层调用成熟隔离工具，不重新发明安全沙箱。普通代码使用专用 Linux VM 原生 isolate 和受控工具链；执行器返回事实，核验器检查测试或标准，Agent 解释并提出下一步。

isolate 官方建议专用执行环境，当前 cgroup 模式要求 v2，且不推荐在容器中运行；当前文档要求 Linux 5.19 或更新内核才能报告内存使用。因此部署方案要按实际主机验证，不直接放进业务服务的容器。[官方手册](https://www.ucw.cz/isolate/isolate.1.html)

编译和运行都需隔离，按语言配置线程、总内存、文件和时间。访客模式短期处理后把结果返回本地并清理，账号模式由业务层持久管理任务与证据。检查崩溃转储、内容日志、临时附件和备份等实际清理路径，不能只删除一个工作目录就宣称无留存。

SQL 使用可重置数据库实例或受控实验环境，管理数据、会话、事务与外层预算；网络使用受控 Linux／FRR 等模板及检查器；数据实验使用锁定依赖的工作区。网络底座选择在小拓扑原型比较后确定，不强行让所有实验通过同一个标准输入输出执行器。

替代方案的触发条件：

- 自建 Piston：若原生 worker 包装工作阻碍原型，可比较其多语言 API；它仍需部署与运行时验收，官方示例使用 privileged Docker，放独立执行 VM；公共 API 已限制授权，不作为商业产品的默认依赖。[官方项目](https://github.com/engineer-man/piston)
- Judge0：若后续大量语言、批量提交和成熟评测接口成为主要需求，再比较其服务；默认持久存储与访客本地要求要重新适配。[官方项目](https://github.com/judge0/judge0)

本次未采用代码。isolate 为 GPL-2.0-or-later；采用和交付时核对具体组件与版本，其他运行时和依赖分别核对。[官方 LICENSE](https://github.com/ioi/isolate/blob/master/LICENSE)

## 5 资源：先限额运行，再测量

建议代码执行 VM 候选为 x86_64、4 vCPU、8 GiB 内存和约 60–80 GiB SSD，先放行一个代码任务，观察排队、编译峰值和清理后再调整。业务服务与数据库另安排；网络实验用独立受控环境。现有服务器配置本轮未重新核对，不能据此保证它能承载这些环境，也不代表已采购。

下面是原型初值，必须用参考程序和正常学生作品校准，并保留任务可调整档位；不是所有课程统一的判题标准。

| 档位 | 资源初值建议 |
|---|---|
| 普通 C／C++／Python／JS 运行 | 约 1 CPU 配额，512 MiB，总 CPU 时间 3 秒、墙钟 10 秒 |
| Java 运行 | 总内存 1 GiB，另设堆与线程限制；启动开销按实际测量调整 |
| 小型编译 | 约 1 CPU 配额、1 GiB、CPU 10 秒／墙钟 30 秒；大型依赖另档 |
| 普通代码文件与输出 | 输入约 1 MiB、临时目录约 64 MiB、输出约 1 MiB；超限与截断明确显示 |
| SQL 小任务 | 独立环境约 1 CPU／1 GiB，语句约 5 秒、锁等待约 1 秒；外层仍有不可绕过的预算 |
| 网络与 AI／ML | 专门声明拓扑、依赖、启动、运行、收敛、文件与闲置预算；不沿用短代码时间限制 |

CPU 时间和墙钟、实际内存与虚拟地址空间分别处理；进程／线程按语言配置。所有限制须测实际是否生效，不凭配置文件认定隔离通过。账号和访客的短期处理、配额与清理边界见 [账号设计](ACCOUNT_AND_DATA_DESIGN.md)。

先测正常、错误、编译峰值、超限、取消、重复提交、资源清理和重建，再决定并发与升级。数据规模、厂商镜像和多人同时实验的容量另测，不承诺固定机器支持多少学生。

## 6 教师默认可见范围

推荐默认在学生明确授权的课程范围内开放：学习目标与任务、学生主动提交的作品、核验依据和来源、帮助程度摘要、待核验项与主动求助的问题。学生加入时看清范围，并能调整或撤销。

推荐按课程授权，共享作品的核验与帮助摘要跟随所提交作品；未提交的私人草稿不默认开放。授权界面列出覆盖的已有记录，以及此后同范围的新提交；额外课程或完整对话片段需另行分享。

关系建立采用两条路径：教师定向邀请，学生接受时确认身份、课程和共享范围，视为双方确认；学生主动申请，教师接受后生效。拒绝或等待不影响自主学习。关系和分享授权分别记录，教师不能单方面认领学生。学生收窄或撤销授权后，停止新的读取与共享，自己的作品和已收到反馈保留；已经导出的副本无法保证收回。

完整聊天、全部私人教材与附件、其他课程历史不默认开放；学生可以单独分享相关片段。教师能维护标准、反馈与提出补充核验，不能修改学生原始作品、认领学生所有权或因为是教师就读取全体学生数据。权限覆盖 API、检索、附件和 Agent，不仅是页面。

## 7 完整答案默认规则

训练活动先提供分层提示，但允许学生主动请求完整答案，不强制等待若干分钟或失败若干次。查看前说明会被记录为帮助；揭示内容、时间和对应尝试留痕。

示例讲解和示范可以直接包含解法；用于检查独立表现的任务开始时说明帮助规则。答案开放和教学帮助本身不另外收取“解锁答案”费用，远程生成仍计入明确的服务额度。开放设计允许多个合理解，不能把未经核对的模型参考解显示为已验证标准答案。

看到完整答案或 Agent 代做后完成，仍保留真实结果，注明帮助；该次不作为独立核验，不给“能力差”结论。学生可解释关键选择，再用新条件的任务获得新的表现证据。独立核验中若选择查看答案，也转为有帮助的尝试，再提供新任务，不用拒绝求助来维持虚假的独立状态。

答案与标准先校核，缺乏可靠依据的任务保持待核验。教师正式考核若未来加入，需要单独明示规则，不覆盖自主训练的默认行为。

## 8 多 Agent：四项职责，按需调用

| 建议职责 | 主要产出 | 典型触发 |
|---|---|---|
| 规划与诊断 | 目标草案、起点、不确定项、路线与下一步理由 | 开始学习、阶段调整、明显证据冲突 |
| 辅导 | 解释、提示、示范与等待学生动作 | 提问、卡住或获得反馈后 |
| 实践任务 | 从经核对任务选择活动、变体，提出新任务草案 | 需要练习、迁移或补先修 |
| 核验 | 工具调用、标准审阅、证据范围与待复核项 | 提交作品、迁移核验或争议 |

建议配置四个明确角色，共用一个受控流程；普通问题只调用必要角色，不要求同时调用四个或使用四种模型。原型先做规划—辅导—核验的真实交接，任务角色优先使用已核对模板，生成新活动时仍须校核。多 Agent 数量不是创新或学习效果证明。

四项职责各有调用入口、输入输出和工具权限，记录实际调用与交接；一次模型输出四段角色发言不能算真实协作。规划与诊断提出路线，辅导提供帮助，实践任务提出任务或变体，核验调用受控工具与审阅标准。路线确认、标准发布和学习状态写入分别由学生动作、内容审核及业务校验控制。

框架推荐自托管 LangGraph 开源库，按条件图组织工具、等待学生、失败和交接；模型供应商单独适配。长期目标、作品、证据、权限与进度保存在自己的业务模型中，框架检查点负责运行恢复。[官方概览](https://docs.langchain.com/oss/python/langgraph/overview)、[持久化](https://docs.langchain.com/oss/python/langgraph/persistence)

采用 Python 版开源库，在自己的服务中运行；托管平台与完整内容追踪服务不作为必需依赖，默认不向外部追踪服务上传私人教学内容。具体库版本在依赖兼容与恢复验收后锁定。流程标识不是授权凭据，各次恢复都校验账号、空间、活动与流程版本。

访客请求只临时运行，等待学生的业务状态返回并存本地，下次按本地输入重新校验并开始受控运行，不为其建立长期框架线程或完整内容追踪。登录模式才使用账号关联的持久恢复；中断恢复可能重新执行节点开头，写入必须幂等。[中断语义](https://docs.langchain.com/oss/python/langgraph/interrupts)

访客下一请求依据本地作品和正式模板重建，不能直接执行客户端提供的任意图检查点、工具指令或权限。登录模式使用账号关联的持久检查点，外部执行、证据写入、进度和额度扣除另以稳定操作标识避免重复；框架恢复不自动保证外部动作只发生一次。

先限制内部轮次和调用预算，例如普通请求不超过两次模型调用，复杂核验按活动给单独预算；这是原型策略，不能因此跳过必要核验。重复故障不无限互相讨论，向学生说明待处理原因。观察实际正确性、学习帮助、等待、成本以及相近预算下单角色方案的差异，再调整配置。

## 9 开发资源与顺序

建议由项目发起人负责产品取舍、材料选择和真实学习；一个有明确交付责任的全栈开发负责可运行原型，AI 辅助编码、整理和检查。条件允许时，分为前端／本地同步与后端／执行编排两名开发，并有课程标准审阅支持。具体是谁和实际投入尚未确定，不据此承诺周数。

按可验收成果推进：

1. 访客学习、登录承接、两类账号、版本与同步、范围授权的基础流程。
2. 一条真实课程活动，包含多角色交接、实际执行或标准核验、提示、独立变体和跨会话恢复；形成可用原型后立即开始本人持续学习。
3. 与本人持续学习并行，按课程矩阵逐门、逐活动类型补齐并验收默认教学范围，以及 SQL、网络与数据实验适配器；发布时明确实际覆盖。公共能力复用测试，课程内容与适配分别检查。
4. 持续复查本人课程中的问题与延迟表现，以及各课程验收、部署恢复和运行成本；按实际证据扩大产品交付。

前两步是中间原型，不把只支持一门课的原型当作已经满足常见课程要求的产品。若人力只有一人，减少同时开发的模块，借用已验证底座，逐步完成范围。

## 10 收费建议

建议先做一个清楚的个人方案：基础本地学习、作品与证据管理、导出以及有明确容量的账号基础同步免费；在线 AI 和标准实验提供有限试用。个人月订阅包含更多辅导与反馈额度及实验时长，高资源任务另设明确额度，用户选择后才使用，不默认自动超额扣费。

额度对学生展示为辅导／反馈与实验使用，Agent 内部交接不分成多项收费。平台故障重试不重复扣正常使用额度。按月起步，暂不做复杂多档套餐或长期预付；教师基础支持保持可用，组织交付、课程维护或私有部署在需要时按范围另报价。

初版建议按有效辅导／反馈请求数和实验使用时长展示额度，内部多角色和模型 Token 只用于成本核算。网络环境启动、编译与失败的计量细则需校准并提前展示；故障重试不另扣重复额度，幂等计量不能仅依赖前端按钮。

订阅结束回到免费方案，已有成果仍可查看、导出和删除，不因到期自动删除作品。超过免费云端容量时暂停新增上传并明确提示，本地继续保存；原件不因上传失败丢失。具体保留政策上线前明示，不以隐含期限清理学习成果。升级增加服务额度与容量，授权、数据归属、真实证据标准和基本学习流程保持一致。

免费基础能力、订阅和资源额度是产品结构建议；类似分层可参考 [Codecademy 方案](https://help.codecademy.com/hc/en-us/articles/6844743588635-Difference-between-Plus-Pro-and-All-Access-Pass)与 [Replit 定价](https://replit.com/pricing)，它们不能替我们证明需求或计算成本。

正式价格建议在本人真实使用后制定，而不是先写一个好看的收入预测。每个完成单元记录实际模型调用、编译／实验、附件与存储、故障重试、内容校核和支持投入；再根据轻／重使用分布估算套餐成本，并验证付费意愿。

原型前设一个可调整总预算，触及上限时告知并停止新增远程消费，本地记录和已同步数据仍可用。预算金额、正式单价、免费额度和容量需结合实际服务报价与测量确定；当前没有已验证成本、付费率、收入或毛利数据。

访客远程试用额度由服务端短期凭证、速率限制与总预算共同约束，不能只信任客户端自述的使用次数；不为限额建立长期访客学习档案，统计尽量采用不含学习内容的汇总。临时凭证和处理期限在实现时明确。

## 11 本轮六项主选方案

以下均为本轮推荐采用的方案，尚未标记为用户正式选定。正式选择后进入流程与架构设计，运行验收通过后才标记可用。

|---|---|---|
| B01 | 规划与诊断、辅导、实践任务、核验四项职责 | 各自可调用和交接，共享版本化证据，按需协作，帮助与核验分开 |
