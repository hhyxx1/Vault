# 架构决策记录

本目录记录实现中需要固定或复审的跨版本技术决定。记录产品需求如何约束方案，列出状态、理由、备选、后果及复审条件。未经审阅与测试的建议不能标为已采用。一个主题一条编号记录；不以 PRD 维护已实现代码参数。

## ADR 状态

- **提议**：候选项；不能作为实施事实。
- **接受**：已授权纳入当前架构基线。
- **替代**：被新 ADR 取代，旧版本仍保留。
- **拒绝**：记录原因，后续重开须提供新依据。

## ADR-0001：多 Agent 工作流编排器

- 状态：提议。
- 需求来源：PRD FR11、FR37–FR39；[Skill 设计](SKILL_DESIGN.md)。
- 候选：在自托管服务中使用 LangGraph 管理可暂停／恢复的角色状态工作流；另需比较直接编写显式状态机的维护成本。
- 尚须验证：学生等待后恢复、异步工具、客户端重连、多步骤取消、角色／Skill 版本固定、并发隔离、调用预算与失败回滚。
- 风险：流程持久状态并非学生证据；每次恢复均重验身份、当前授权和任务版本，不能恢复已撤销权限或注入旧答案。
- 接受条件：架构原型通过恢复与权限测试；软件许可、依赖维护和可迁移性经审阅；阶段流程无隐式无限重试。
- 注：这是实现选型决策，不代表 PRD 已指定编排器或已有运行代码。
