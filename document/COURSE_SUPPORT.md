# 常见课程与执行环境支持矩阵

日期：2026 年 10 月 3 日。

状态：对应 PRD v1.3 的支持要求与验收方案；当前未实施本矩阵的验收，不能据此宣称现有系统已支持下列能力。CS01–CS13 以及 C、C++、Java、Python、JavaScript 与独立 SQL 环境属于第一阶段正式范围；运行版本、依赖和专用环境仍须验证，增减产品范围需同步需求基线。

## 1 支持范围如何定义

产品面向整门课程的多 Agent 教学与持续学习。学生可以只提供课程名称、目标或当前问题，从经核对的默认课程范围开始；也可以带教材、课程大纲、讲义或其他合规资料，对齐章节与目标。系统在同一问题中交替组织必要理论、学生尝试、真实反馈、解释与修改，保存作品，在之后的会话继续。本人选用哪门课程自测，不限制其他课程的学习入口。

各课程路线保留概念、先修、原理和适用条件，活动与这些目标对应。零基础可先短说明或示范，实践可以是推演、反例、证明和设计，也可以是编码或实操；不强制每门课变成大项目。具体体验及往返流程见 [学习闭环设计](LEARNING_LOOP_DESIGN.md)，讲解或视频完成不作为进入实践的门槛。

教材不是启动前提。默认课程知识范围、先修、活动与核验标准必须由产品维护并有可检查依据；材料解析仅是可选能力。无资料启动、资料对齐及跨资料表述差异均需验收。

各领域支持未登录学习：个人资料与记录仅本地持久保存，可用在线工具临时处理；登录后关联与同步本人空间。未登录并不保证全部工具离线运行。存储、教师关联与账号隔离按 [账号与数据设计](ACCOUNT_AND_DATA_DESIGN.md) 执行。

每门课程分别核对三件事：

1. 通用学习流程：材料、目标、活动、尝试、反馈、证据、恢复与后续安排。
2. 内容覆盖：已经人工核对的知识单元、资料、任务及标准；其他内容生成后应标明待核对。
3. 实验支持：当前能够真实运行或核验的实验类型、环境与限制。

通用流程须落实为每个活动的契约，不能只复用聊天页面。学生动作、产物、核验依据、帮助、迁移、恢复与下一步以及 CS01–CS13 的具体闭环案例，见 [跨课程真实学习与证据闭环设计](LEARNING_LOOP_DESIGN.md)。记录行为和作品可以自动化，但理解与开放问题不保证全部自动评价。

课程名称或聊天入口不足以证明支持。一个单元通过功能验收可以证明对应流程可用，但不能写成该课程所有章节、题目和实验都已验证。没有专用实验环境时，可以继续概念学习、推演和已有产物分析，并清楚说明尚不能核验的部分。

课程分类用于查漏与组织活动，不限定学校的课程名称。知识领域参考 [CS2023 官方课程知识领域](https://csed.acm.org/knowledge-areas/)，下表是本项目的课程组织方案，不是该指南的逐字课程清单。

### 1.1 完整课程蓝图与学生学习范围

CS01–CS13 每门课都需要建设可审阅的完整默认蓝图，列出声明范围和深度、章节／主题、知识单元、核心与扩展目标、先修、理论—活动—核验对应、资料依据及维护责任。代表性案例表用于验收起点，不能替代全课蓝图；目前这些蓝图尚未交付，不将计划写成完整内容已就绪。

完整包的字段结构、关系、内容审校及课程发布门槛见 [课程内容规范](COURSE_CONTENT_SPEC.md)；栈单元文件只是 schema 样例且仍待专家审校，不决定本人自测课程。CS01–CS13 全量蓝图、所有范围节点的活动及核验路径均是第一阶段交付门槛；逐门验收记录和 46 项系统需求追踪见 [开发计划](DEVELOPMENT_PLAN.md) 与 [综合测试计划](TEST_PLAN.md)。按工程切片先跑通少量单元，不等于降低全课程最终范围。

学生可以查看全课内容和自己的目标证据分布，不需指定教材。个人短期目标引用蓝图中的目标，但不缩减整课分母；核心、选修与当前计划分别展示。已定义但缺少环境或标准的目标保留并说明限制，不能从统计中静默隐藏，也不能标为学生未掌握。

只统计稳定可检验目标：目标可被多个活动或章节引用，仍计一次；章节／知识单元父节点不与子目标重复计数。不同目标的难度和重要性可能不同，目标数量占比不代表知识总量、考试分数或剩余学习时长。详细证据与当前统计规则见 [学习闭环设计](LEARNING_LOOP_DESIGN.md)。

每门课的蓝图提供动态图谱所需的层级归属、先修及概念／应用关系，保留稳定引用、类型、方向、来源与版本。个人证据摘要叠加在结构上，组织节点聚合其去重目标，关系连线不传递达标结论；学生可从节点查看依据并进入理论与实践活动。图谱交互、等价文字视图、有效事件更新与授权按 [学习闭环设计](LEARNING_LOOP_DESIGN.md#62-动态知识图谱与学习导航) 和 [图谱验收](COURSE_VALIDATION_PLAN.md#45-动态知识图谱验收) 核对，不能由一个局部示意宣称整课内容已交付。

### 1.2 教师自建课程的支持边界

CS01–CS13 是平台完整交付的默认课程基线，课程创建不受其数量或名称限制。第一阶段教师可以通过大纲／PPT／资料、授权模板或空白创建独立课程，AI 辅助形成草案；教师审阅范围、资料可见性、活动与标准后按版本定范围发布。

自建课程共用学习工作区、图谱、独立目标统计、Agent／Skill、证据与恢复流程。执行能力逐活动检查：复用已验收适配器，开放设计采用人工复核，缺环境时明示外部实践／作品提交或待适配；外部证据保留来源，不自动升级为平台核验。学生问答仅引用当前有权访问且明确学生可见的资料／发布物，私有参考不因生成课程而开放。

教师课程来源、内容责任、范围发布和平台官方验收分别显示。自建课程数不替代默认 13 门的全范围验收；模板复制不带私人作品／授权，课程更新不静默改写历史证据。参见 [课程内容规范](COURSE_CONTENT_SPEC.md)、[用户流程](USER_FLOWS.md) 和 [RAG 权限设计](RAG_AND_RESOURCE_DESIGN.md)。

## 2 课程基线

以下课程均需支持第 1 节的通用流程，表中活动是每个领域最低需要验收的代表性案例，不是整门课程的全部内容。

| 编号 | 课程或领域 | 代表性学习活动 | 结果核验方式 | 专用实验边界 |
|---|---|---|---|---|
| CS01 | 程序设计基础 | 读代码、调试、条件循环与函数、小功能实现 | 编译或解释执行、测试输入、边界情况、解释和独立变体 | 语言和依赖以环境清单为准 |
| CS02 | 面向对象程序设计 | 类、接口、继承组合、小型多文件任务 | 编译、单元测试、对象关系与设计说明 | 不默认提供完整桌面或移动应用环境 |
| CS03 | 数据结构 | 栈队列、树与图的实现、执行过程和错误分析 | 行为测试、状态轨迹、边界输入、独立应用 | 动态演示用于辅助理解，不能代替测试 |
| CS04 | 算法设计与分析 | 搜索排序、递归、贪心或动态规划 | 正确性测试、反例、复杂度与推理标准 | 运行耗时需记录环境，不能直接作为复杂度证明 |
| CS05 | 离散数学 | 命题逻辑、集合关系、图论和证明 | 真值表、可复核推导、反例、已核对标准，必要时人工复核 | 自然语言证明不能仅凭模型一句“正确”通过 |
| CS06 | 计算机组成原理 | 数制与编码、数字逻辑、指令和存储状态推演 | 真值表、确定性计算、状态变化与参考轨迹 | 实物电路、完整处理器或 FPGA 实验需另配环境 |
| CS07 | 操作系统 | 调度、内存、同步与进程情境 | 可复核推演、受控模拟、小程序结果和场景变体 | 不修改业务服务器内核或运行不受控系统实验 |
| CS08 | 计算机网络 | 地址、路由配置、报文观察、协议过程与故障排查 | 浏览器隔离拓扑、实际状态与双向通信检查、定向抓包、解释和变体 | 基础模板需真实验收；厂商 CLI、复杂拓扑和外部网络实验另配环境 |
| CS09 | 数据库 | 建模、查询、约束与基础事务 | 隔离数据库真实执行、结果集比较、约束和设计标准 | 每次任务使用独立可重置数据，不使用业务库 |
| CS10 | 软件工程 | 需求、接口、测试设计与小型项目步骤 | 可检查约束、设计评价标准、代码测试及任务产物 | 长期运行的 API 和复杂工程需工作区适配器 |
| CS11 | 编译原理 | 词法、语法、自动机和小型分析器 | 给定语言规则、已知输入输出、解析结果和推演 | 完整编译器工程与目标平台需另行配置 |
| CS12 | 人工智能基础 | 搜索、知识表示、推理与问题建模 | 已知问题的搜索轨迹、约束检查、程序结果与解释 | 不把模型输出本身作为推理正确性的唯一证据 |
| CS13 | 机器学习基础 | 数据处理、训练验证划分与小规模模型实验 | 固定数据与依赖、随机种子、指标计算及解释 | 大规模数据、GPU 训练和外部模型服务需单独支持 |

信息安全、并行与分布式系统、图形学、人机交互和其他专业选修可沿用相同材料与学习流程；其专用活动和实验应新增矩阵条目及验收，不能只因为能上传教材就宣称实验已支持。

## 3 每个领域的验收

每个 CS 编号按实际要求的活动类型分别建立真实验收记录，至少覆盖：

- 不提供教材，仅给课程名／目标，从默认课程范围开始真实教学活动。
- 使用实际合规资料对齐课程，核对解析内容、章节及资料出处；资料是可选输入。
- 确认一个可检查的目标，提供符合该领域的起步任务。
- 核对整课蓝图、目标与先修范围，验证课程／章节／个人计划概览及证据展开；当前内容仅属已定义范围时如实标明。
- 核对动态图谱关系、父节点聚合及节点学习入口；展开、选择与过滤不改整课分母，证据更新只影响实际适用目标，文字视图与权限一致。
- 在同一单元交替开展理论与实际活动；反馈说明当前结果与原理的关系，记录尝试、解释、修改和提供的帮助。
- 检查必要说明先行、自由尝试、依据实际结果调整支持及关键节点核验；路线不能遗漏声明范围内的重要理论和先修，不要求每次操作测评。
- 用适合该任务的方式核验，包括预设正确产物和故意错误产物。
- 保存证据，明确未知、帮助后完成及独立核验等状态。
- 退出后恢复到具体活动、作品和下一步；能够继续到后续单元。
- 触发一次工具或评价失败，确认没有被写成学生能力不足或自动通过。
- 修改作品后旧结果不错误复用；迟到结果、重复提交及标准修订不自动推进。
- 缺乏可靠依据的证明或设计能保持待核验；待复核时可以继续其他学习。

课程内容和核验案例在发布前人工核对，纳入合理的替代答案和故意错误产物。对已经覆盖的活动标记通过，对尚未覆盖的活动标记待验收或暂不支持，并记录原因。不能仅凭算法实现通过就宣称证明活动支持，或凭调度推演通过就宣称真实并发和内核实验支持。当前所有领域均为“待实现、待验收”。

发布记录至少列出课程与单元、已验收活动类型、环境与规则版本、证据位置、恢复边界、未覆盖内容、结果、复核人及日期。只验收一个案例时，支持标识限定于这个案例的实际能力，不给整门课统一勾选“全部支持”。

每门声明支持的课程均须分别验收；不同课程之间可以复用公共能力测试，但不能用数据结构通过来推定离散数学、网络或其他课程通过。本人完整学习一门课用于检查持续使用，不承担其余课程的全部验收。课程范围、逐类型检查、Agent 协作和版本回归的分工见 [课程与多 Agent 验证方案](COURSE_VALIDATION_PLAN.md)。

## 5 执行与核验的产品行为

学生选择实际可用的语言和版本 → 编辑或导入允许的代码文件 → 设置输入 → 提交执行 → 查看编译与运行输出 → 修改重试或提交核验。

结果分为独立维度：

| 维度 | 示例状态 | 能说明什么 |
|---|---|---|
| 执行 | 排队、编译中、运行中、成功、编译错误、运行异常、超时、资源超限、环境失败、取消 | 工具真实运行的状态 |
| 核验 | 未核验、核验中、满足测试条件、未满足、核验失败 | 是否满足这次测试集或评价标准 |
| 学习判断 | 未知、帮助后完成、独立完成当前任务、迁移待验证 | 在具体证据范围内的学习表现 |

无可靠测试集或比较规则时，即使执行器返回成功，也显示“运行成功，尚未核验”。通过有限测试不证明所有输入都正确；当前任务合格不自动证明理解、迁移或长期掌握。

每次保存源码或作品版本、语言与环境版本、输入、真实输出、退出状态、测试集和标准版本、每个测试点结果、资源结果、提供的帮助与重试关系。记录输出截断和超时，不让迟到结果覆盖新的作品核验。

测试比较方式包括精确输出、明确的空白处理、浮点容差、无序集合或其他经核对的检查器。数据库任务尤其应处理顺序、重复值和 NULL；证明与设计任务使用可解释标准，不套用标准输出判题。

测试集先用参考产物和故意错误产物验证。由 AI 生成的题目、测试和答案，不能仅靠同一次生成互相保证正确。学习练习可以展示示例与失败原因，独立核验使用不同或未提前展示的任务条件。

## 6 执行环境验收

实际实现必须核对以下情境并保存结果：正确代码、编译或语法错误、运行异常、输出错误、无限循环、内存或输出超限、服务不可用、取消、重试和重复请求。隔离还应检查不能读取宿主敏感文件、访问业务库或外部网络。

不同语言使用合适的资源配置；编译与运行分别限制时间、内存、进程、文件和输出。执行服务部署与业务服务隔离。访客结果仅在本地持久保存，远程任务限时处理并清理；账号任务与状态在本人空间持久化。专用实验若需要局域通信，由适配器控制，不能开放通用外网访问。

这些是后续实现验收要求，本次仅完成文档。执行引擎、判题逻辑与学习解释的设计取舍见 [设计参考与逻辑取舍](DESIGN_REFERENCES.md)。

## 7 网络课程基础实操

网络实操使用受控拓扑与服务端实验节点，不依赖学生本地安装厂商模拟器。先验收“两台主机经路由节点跨网段通信”：学生预测路径、配置地址与路由、观察 ARP／ICMP、提交检查并解释结果，再在改变网段或注入故障的任务中验证。

采集拓扑版本、配置差异、关键地址与路由状态、可获取的终端记录、抓包和每次检查结果。不能只检查 ping 通，也不能把输入过正确命令当作配置正确。现有自由终端无法保证逐条命令结构化，缺失证据应标明。

DNS、TCP、动态路由和交换实验逐个新增模板和检查器；通用 Linux 网络行为与厂商设备行为分别声明。已选containerlab／Linux／FRR及每租约VM边界，详细方案见 [网络实验工作台设计](NETWORK_LAB_DESIGN.md)。本节能力仍待实现与验收。

## 8 所有课程共用的检查边界

- 阅读、观看、讲解和讨论是合理学习活动，单元需要关联预测、解释、推演或实际作品才能核验理解。
- 有限测试、推演和仿真的结论限定于测试条件及模型；不能替代一般证明、实物行为或全部运行交错。
- 证明与开放设计使用有依据的标准审阅，必要时复核；证据不足保持待核验，不能以多个 Agent 赞同自动通过。
- 数据实验记录划分、处理、依赖、随机配置和实际结果；高分不单独证明理解，种子不保证跨环境完全一致。
- 保存对应作品和恢复条件；代码、推导、数据库、数据实验、项目和网络不能只靠恢复聊天续学。
- 在新条件与之后的任务中继续获取证据，记录实际帮助与时间；基础入口需实现，智能长期调度不在本矩阵中宣称已经完成。
