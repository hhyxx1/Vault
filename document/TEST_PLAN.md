# 综合测试与需求追踪计划

版本：v0.6

状态：按 PRD v1.5 与 FR48 对齐的测试设计；工程、账号同步和个人课程手动切片已执行部分测试，完整 FR／P0／课程验收仍待执行。13 门默认课程目前完整交付 0／13；个人课程尚无完整图谱、AI 辅导、真实执行和可靠核验，TC-48A–H 的完整验收待执行。课程专项策略沿用 [课程与多 Agent 验证方案](COURSE_VALIDATION_PLAN.md) 和 [课程支持矩阵](COURSE_SUPPORT.md)。

## 1 验证目标

验证平台是否按需求为学生提供跨会话的真实学习；课程内容是否全量覆盖及可核对；工具执行、Agent、教师权限、访客归属和同步是否如声明工作。分别报告软件功能、每门课能力、学习效果观察和安全／运营，不用功能通过推导提分或掌握效果。

## 2 测试层与职责

| 层 | 测什么 | 建议证据 |
|---|---|---|
| 内容／schema 校验 | 字段、ID、版本、引用、目标映射、层级归属与必须满足的先修无环、其他关系按类型校验及范围覆盖 | 概念／应用关系允许合理的环；结构校验日志不代表教学正确 |
| 单元／属性 | 状态转换、权限判定、幂等、状态聚合、统计去重、答案策略 | 自动运行结果、随机／性质边界样例 |
| API 契约 | 输入校验、身份、错误、版本冲突、事件序号和迟到回调 | 契约测试报告 |
| 集成 | 前端／本地空间／服务／数据库／消息／工具链配合、部分失败 | 可复现环境中的关联事件 IDs |
| 端到端 | UF01–UF09 关键角色流程、学生等待和真实恢复 | 固定版本任务全程记录 |
| 执行隔离 | 语言／SQL／网络真实执行、资源／网络／文件边界、输出限制 | 镜像哈希、资源策略、工具原始日志、清理验证 |
| Agent 与 Skill | 选择、交接、内容依据、答案守规、费用预算、恶意输入、工具失败 | 独立人工标注的参考 case 和步骤事件 |
| 默认课程 | CS01–CS13 全蓝图及所有声明活动类型逐门检查 | 每课覆盖矩阵与教学／运行标准审阅报告；当前完整课程 0／13 |
| 学生个人课程 | 13 门之外无教师、无教材和无模型的自主启动，以及私人范围、真实活动、证据、恢复与权限 | TC-48A–H；未审校范围和能力缺口明示，不抵扣默认课程验收 |
| 安全、数据与可靠性 | 越权、身份切换、同步冲突、删除、日志保留、备份和恢复 | 风险用例证据、数据核对和恢复记录 |
| 产品验证 | 自主启动、学生理解反馈、真实持续学习阻碍和运维成本 | 有范围声明的真实使用观察；不把模拟数据作为效果指标 |

测试分为提议、评审通过、运行中、通过、失败、阻塞、豁免和过期。一个测试的“通过”只适用于记录的 commit、课程／接口／工具／标准版本及输入。豁免须注明理由、期限和批准人。

## 3 跨课程全量验收规则

CS01–CS13 每门分别出报告。内容和课程全范围验收不依赖只抽一个示例：

1. 全部声明章节／知识单元／可检验目标必须与事先经课程审阅的完整范围和深度清单逐项对照，不留“未写而默认为已覆盖”的缺口；所有排除项公开说明。验收不能临时缩小范围，核心缺口不得因工具不足而排除。
2. 每个目标有来源／深度、必要条件、所属核心／选修、先修关系、适合的理论和学生活动、产物、支持工具、核验或人工复核方式、帮助／失败／恢复／下一步。
3. 所有活动类型在对应课程中有代表性的正确、错误、边界、证据不足和环境失败 cases；每个自动 checker 逐条件测试参考解、反例与合理替代解，开放题校验复核流程。
4. 无教材入口能在完整默认内容范围学习；选资料能检验术语／章节映射且不覆盖课程基线。
5. 按每门课的专用支持矩阵验收执行／实验。已定义不能真实自动检查的活动可进入人工复核并声明限制；不能用一门课的代码结果或其他课程的 checker 推断支持。
6. 全课程清单和状态投影一致，核心／选修／个人范围不互相偷换分母；目标引用去重、目标版本更新留痕。

具体 CS01–CS13 差异性场景引用 [课程支持矩阵](COURSE_SUPPORT.md) 和课程专项计划。第一阶段验收只有在 13 门全通过后方可完成；部分课程未通过时明确只属内部试验状态。

FR48 学生个人课程另设端到端与权限验收。它验证学生能从 13 门之外自行开始并持续学习，不能把私人草案当作平台已审校课程，也不能用个人课程数量或局部目标通过代替默认 13 门的完整验收。

### 5.1 前端品质追踪与验证

NFR-UI01 → P00–P11／UF01–UF10 → QT-09 → VQ-01–VQ-08。八项当前全部为**待测**，检查细则和报告格式以 [前端设计与品质标准](FRONTEND_DESIGN_STANDARD.md) 为准。QT-06 的访问性与响应式底线、QT-04 的性能测量和 TC-01–TC-48 的功能正确性仍分别验证，不能因视觉评审通过而省略。P11 个人课程页面及其空白、草案、错误和恢复状态也须纳入实际前端复核。

- 各页面用真实的中文长内容、公式、代码、表格、密集图谱和错误记录检查；测试样例须明确标注且不进入真实学习证据。
- 覆盖加载、等待、空数据、成功、失败、离线、冲突、受限和恢复等适用状态，验证键盘、鼠标、触摸与减少动态效果。
- 记录浏览器／设备／视口、版本和截图；动效与微交互还需实际操作记录或录像，静态截图不能替代。
- 自检 → 记录问题 → 修正 → 受影响功能回归 → 独立复核；复核发现明显改进项则继续循环，不限定为固定轮数。
- 达标后新发现的问题重新进入修正与复核。未覆盖的页面／状态／设备不能标成通过。

## 7 执行与发布门

- 每个变更先运行其相关单元／契约用例和课程／流程回归；涉及权限、数据归属或客体版本变更时运行对应安全／同步矩阵。
- PRD／流程／内容／接口／数据 schema 变化应同步 RTM；没有实现或测试证据的 FR 状态保持待测。
- 平台默认课程 bundle 未通过全量范围审校或适用 activities 不全时不得标记完整支持；任一 CS01–CS13 在第一阶段不通过即未达到全课门槛。教师范围发布与平台官方验收分开，不能把教师自建课的发布数抵扣默认 13 门的验收。
- FR48 发布前须完成 TC-48A–H 的自主启动、私人范围、学习闭环、归属与权限证据；个人课程未审校或专用工具缺失时只能按实际能力展示，不能用于填补默认课程验收缺口。
- FR44–FR46 发布前必须有自建课与资料 RAG 权限测试证据，越权／受限答案泄露属阻断项；索引清理未完成不能成为继续提供失效资料的理由。
- 第一阶段发布必须无未批准阻断缺陷，P0 FR 全部有通过证据，所有性能／留存／恢复阈值经过负责人评审，运行基线可回滚；P1 延期有显式记录。
- 前端交付必须通过 QT-09 八维自检和独立复核，覆盖全部交付页面、适用状态和设备矩阵；不得留下明显可提升之处，也不能以课程验收或功能通过替代前端品质验收。
