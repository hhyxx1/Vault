# 综合测试与需求追踪计划

版本：v0.1

状态：尚未执行测试；本计划定义设计和首发验收方案，不代表任何 P0／课程已经通过。课程专项策略沿用 [课程与多 Agent 验证方案](COURSE_VALIDATION_PLAN.md) 和 [课程支持矩阵](COURSE_SUPPORT.md)。

## 1 验证目标

验证平台是否按需求为学生提供跨会话的真实学习；课程内容是否全量覆盖及可核对；工具执行、Agent、教师权限、访客归属和同步是否如声明工作。分别报告软件功能、每门课能力、学习效果观察和安全／运营，不用功能通过推导提分或掌握效果。

## 2 测试层与职责

| 层 | 测什么 | 建议证据 |
|---|---|---|
| 内容／schema 校验 | 字段、ID、版本、引用、目标映射、关系图无环和范围覆盖 | 结构校验日志；不代表教学正确 |
| 单元／属性 | 状态转换、权限判定、幂等、状态聚合、统计去重、答案策略 | 自动运行结果、随机／性质边界样例 |
| API 契约 | 输入校验、身份、错误、版本冲突、事件序号和迟到回调 | 契约测试报告 |
| 集成 | 前端／本地空间／服务／数据库／消息／工具链配合、部分失败 | 可复现环境中的关联事件 IDs |
| 端到端 | UF01–UF08 关键角色流程、学生等待和真实恢复 | 固定版本任务全程记录 |
| 执行隔离 | 语言／SQL／网络真实执行、资源／网络／文件边界、输出限制 | 镜像哈希、资源策略、工具原始日志、清理验证 |
| Agent 与 Skill | 选择、交接、内容依据、答案守规、费用预算、恶意输入、工具失败 | 独立人工标注的参考 case 和步骤事件 |
| 课程 | CS01–CS13 全蓝图及所有声明活动类型逐门检查 | 每课覆盖矩阵与教学／运行标准审阅报告 |
| 安全、数据与可靠性 | 越权、身份切换、同步冲突、删除、日志保留、备份和恢复 | 风险用例证据、数据核对和恢复记录 |
| 产品验证 | 自主启动、学生理解反馈、真实持续学习阻碍和运维成本 | 有范围声明的真实使用观察；不把模拟数据作为效果指标 |

测试分为提议、评审通过、运行中、通过、失败、阻塞、豁免和过期。一个测试的“通过”只适用于记录的 commit、课程／接口／工具／标准版本及输入。豁免须注明理由、期限和批准人。

## 3 跨课程全量验收规则

CS01–CS13 每门分别出报告。内容和课程全范围验收不依赖只抽一个示例：

1. 全部声明章节／知识单元／可检验目标必须与版本化课程范围逐项对照，不留“未写而默认为已覆盖”的缺口；所有排除项公开说明。
2. 每个目标有来源／深度、必要条件、所属核心／选修、先修关系、适合的理论和学生活动、产物、支持工具、核验或人工复核方式、帮助／失败／恢复／下一步。
3. 所有活动类型在对应课程中有代表性的正确、错误、边界、证据不足和环境失败 cases；每个自动 checker 逐条件测试参考解、反例与合理替代解，开放题校验复核流程。
4. 无教材入口能在完整默认内容范围学习；选资料能检验术语／章节映射且不覆盖课程基线。
5. 按每门课的专用支持矩阵验收执行／实验。已定义不能真实自动检查的活动可进入人工复核并声明限制；不能用一门课的代码结果或其他课程的 checker 推断支持。
6. 全课程清单和状态投影一致，核心／选修／个人范围不互相偷换分母；目标引用去重、目标版本更新留痕。

具体 CS01–CS13 差异性场景引用 [课程支持矩阵](COURSE_SUPPORT.md) 和课程专项计划。第一阶段验收只有在 13 门全通过后方可完成；部分课程未通过时明确只属内部试验状态。

## 5 其他质量与安全测试

| 编号 | 核对条件 | 阈值策略 |
|---|---|---|
| QT-01 | 访客、学生、教师、维护者数据越权与检索／缓存／Agent 工具旁路 | 按威胁模型每次发版运行；越权访问应零通过 |
| QT-02 | 不可信代码：文件／网络／资源／进程逃逸，跨任务残留和清理 | 以隔离设计列出每项攻击面及预期封锁结果；第三方安全审阅列发布门 |
| QT-03 | 流程中断、断线、重复事件、队列延迟、异步工具回调、取消 | 所有状态转换及幂等路径有契约 tests；最终状态唯一、归属不漂移 |
| QT-04 | 容量／性能、模型高延迟、课程图谱加载、同步大批次、执行配额 | 先记录硬件／数据集／并发模型测基线，发起人评审目标后锁阈值；超限降级可用，不能事后调整阈值掩盖失败 |
| QT-05 | 备份、恢复、升级、数据库迁移、课程包回滚、缓存作废 | 按部署与数据风险制定 RPO／RTO 目标并演练；旧版本不能改写既有 evidence provenance |
| QT-06 | 访问性与响应式 UI、中文内容、普通键盘和窄屏 | 与用户流程原型逐页走查；状态文字可读，键盘完成关键闭环，无溢出／遮挡 |
| QT-07 | 日志／服务提供方留存、访客过期删除、账号删除／导出、审计字段最少化 | 按已批准的保留期与用途表逐条测试；清理可证明，失败告警 |
| QT-08 | 课程内容与 AI 教学一致性、合理替代答案、教师审核负担 | 对盲评标注样本由独立审阅人复核；模型自评不作唯一通过 oracle |

## 6 全课程测试报告格式

每门记录课程／蓝图版本、负责人／审校人、声明范围、目标数与去重规则、内容覆盖报告、逐类型活动矩阵、资料出处、环境／checker／标准版本、正确／错误／替代／未知 cases、Agent／帮助控制、作品和证据位置、未覆盖／限制、失败／修复／回归结论、复核签署与日期。测试固定于 commit 与内容 bundle hashes。

个人真实学习报告单独记录，包含真实课程、会话、学习产物与实际困难。测试 fixtures、模型捏造产物和本地真实学习材料清楚区分，不将私人作品提交 Git。

## 7 执行与发布门

- 每个变更先运行其相关单元／契约用例和课程／流程回归；涉及权限、数据归属或客体版本变更时运行对应安全／同步矩阵。
- PRD／流程／内容／接口／数据 schema 变化应同步 RTM；没有实现或测试证据的 FR 状态保持待测。
- 课程 bundle 未通过其全量范围审校或适用 activities 不全时不得标记已支持；任一 CS01–CS13 在第一阶段不通过即未达到用户要求的第一阶段全课门槛。
- 第一阶段发布必须无未批准阻断缺陷，P0 FR 全部有通过证据，所有性能／留存／恢复阈值经过负责人评审，运行基线可回滚；P1 延期有显式记录。
