# 教学 Skill 与 Agent 分工设计

日期：2026 年 10 月 2 日。

状态：按从需求重做的方向提出的产品方案，尚未实现和验收。本文不使用现有代码判断能力，补齐此前 PRD 未完整纳入的多 Skill 自动生成与教师、学生提供 Skill；具体格式和角色配置仍为建议。

## 1 三种对象分别负责什么

| 对象 | 作用 | 示例 |
|---|---|---|
| Agent | 在流程中承担角色职责，选择适用方法与受控工具 | 辅导、实践任务、核验 |
| 资料 | 提供教学内容与可检查依据 | 教材、讲义、笔记、官方规则及任务标准 |
| Skill | 可复用、版本化的教学方法或流程包，规定适用条件、步骤、学生动作与检查 | 状态跟踪、反例构造、失败测试引导调试 |

Skill 的教学说明可以包含提示词，但还要有输入输出、依据、产物、核验和恢复契约。它不自动成为 Agent，不授予权限，也不直接证明某门课已支持。一个 Agent 可以按阶段使用多个 Skill，同一方法也可以供不同角色使用。

通用教学方法、具体课程内容和执行工具适配器分别维护。多 Skill 指在一次学习活动中按实际需要选择或组合方法，不要求全部加载，也不要求每个知识点都生成一个新包。

## 2 角色建议：四项学习职责加按需设计职责

| 职责 | 边界 |
|---|---|
| 规划与诊断 | 协商目标、引用表现、安排路线，提出需要的方法或先修补充 |
| 辅导 | 使用适用 Skill 讲解、提示和示范，之后等待学生动作 |
| 实践任务 | 为当前学生选择具体活动、数据、变体与项目步骤 |
| 核验 | 检查学生表现和 Skill 的适用标准，调用实际工具、记录不确定项 |
| 课程与 Skill 设计 | 生成与修订可复用课程结构和方法草案，提出试用案例；不能自行发布或写入已掌握 |

五项职责不等于五个常驻聊天窗口或每轮五次模型调用。普通教学使用必要学习角色，出现方法缺口、新课程／资料、投稿或修订时才调用设计角色。解析文件、执行程序和保存记录由工具与业务服务完成。

设计与核验分别调用并保留依据。另一角色赞同不能单独证明正确；校核还需规则、参考产物、故意错误产物、合理替代方案、真实运行及必要人工审阅。教师和内容维护者负责对应发布，不把每次私人自学变成教师审批。

## 3 Skill 应包含的信息

| 字段组 | 最少内容 |
|---|---|
| 身份与范围 | 标识、作者／所有者、人工或生成来源、版本、可见范围、状态 |
| 适用条件 | 课程／知识目标、先修、适用活动与限制；不适用的情况 |
| 输入输出 | 当前目标、授权资料、任务与作品输入，预期教学步骤与学生产物 |
| 教学方法 | 讲解、提问、示范、尝试、等待与反馈的阶段或分支 |
| 依据与核验 | 内容来源、评价标准、测试数据／比较方式、替代解法、待复核范围 |
| 工具需求 | 平台已批准的工具标识、环境与资源需求；声明不等于获准 |
| 帮助与答案 | 提示范围、帮助记录方式，继承实际任务来源与答案策略 |
| 恢复与失败 | 保存对象、重建条件、失败与缺失证据处理、预算与结束条件 |
| 校核与发布 | 检查、试用及审阅记录，发布范围、更新、停用与替代版本 |

具体文件协议在技术设计中确定。首版建议提供结构化编辑器和 Markdown／JSON 导入，将输入转换为平台可校验格式；不会将任意上传文本当作系统权限指令。

## 4 自动生成、选择与组合

自动生成能力在新版保留并重新设计，流程为：

目标或适配缺口 → 检索有权使用且适用的已有 Skill → 必要时生成草案 → 结构与权限检查 → 私人试用 → 独立内容校核 → 主动启用或按范围发布。

先复用已有方法。生成结果明确标为草案，给出适用条件、依据和待核对项；没有资料也可依据已核对的默认课程范围提出草案，缺少可靠标准时保持未核对。

私人试用可在结构与权限检查后进行，不必等待教师批准；界面说明内容校核状态，不让未经校核的规则写入平台可信通过。共享或课程发布前，按范围完成必要校核与权限检查。结构有效、场景试用、内容已核对和已发布分别记录。

选择与组合先检查授权、答案策略、工具可用性、版本和预算，再按目标、活动与学生表现选择。每阶段只加载需要的内容，记录采用原因、角色、顺序／分支和结果。存在冲突时明确选择或停止冲突部分，不让相互矛盾的 Skill 各自覆盖学习事实。

例如数据结构活动可依次使用状态跟踪、失败测试调试和新条件迁移；离散数学可使用假设检查与反例构造；网络可使用路径预测、实际状态排查和改变拓扑检查。每种方法都需要对应环境与标准，文字生成不能替代实操。

## 5 教师与学生均可提供

| 场景 | 默认行为 |
|---|---|
| 教师私人 Skill | 创建、导入、编辑与私人试用，用于备课或本人学习 |
| 教师课程发布 | 发布选定版本和范围，学生看到来源、适用目的、活动与答案规则 |
| 学生私人 Skill | 自主创建、导入、编辑和试用，不需关联教师；默认私人 |
| 学生主动分享 | 选择定义和范围，接收者选择采用；不自动启用或连带分享原始个人数据 |
| 未登录 Skill | 定义、草案、试用和使用记录仅本地持久保存，在线服务短期处理；登录后关联并同步 |

方法作者、当前所有者、内容审阅与发布权限分别记录。教师身份不自动证明方法正确，学生投稿也不因此取得教师或平台维护权限。分享前检查私人案例、资料附件、受限答案与来源权限；分享一个方法不等于分享全部学习记录。

更新产生新版本，活动固定所用版本，不静默覆盖旧尝试、帮助和核验。停用或撤销停止新的加载／分发，进行中活动说明影响并提供替代方案，已产生作品和记录保留。已经复制或下载的内容无法保证收回。

## 6 权限与首版边界

平台权限、实际任务的发布与答案策略、资料授权及执行预算始终生效。用户 Skill 不能改账号角色、绕过教师受限答案、访问其他资料、批准自己的检查结果或直接宣布掌握。学生修改私人评价方法时保存来源，不将旧失败自动改成平台可信通过。

首版支持声明式教学步骤、资料引用、任务模板、评价标准、测试数据和调用平台已有工具。运行代码、SQL、网络与数据实验继续由平台适配器执行和验收；Skill 声明工具需求不证明工具已存在。

Skill 自带任意脚本、安装依赖、注册外部 API／MCP、操作系统或浏览器等新增执行扩展后续单独设计。这里暂缓的是投稿包扩展执行能力，不能缩减 PRD 已要求的多语言编译和各课程实操。

## 7 验收与真实学习

按 [课程与多 Agent 验证方案](COURSE_VALIDATION_PLAN.md) 检查师生导入、自动草案、试用、独立校核、分享权限、多 Skill 组合、版本、停用、恢复与失败。CS01–CS13 各自验证实际活动；数量、生成成功、格式通过或另一角色赞同不等于课程覆盖或学习效果。

Skill 的使用轨迹是系统行为；学生实际尝试、作品、帮助、新条件及后续表现才形成学习证据。分别记录。本人持续学习用于观察方法是否有用，不预填效果或采用率。
