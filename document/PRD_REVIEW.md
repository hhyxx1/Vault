# PRD v1.0 定版评审记录

评审日期：2026 年 10 月 3 日。

评审对象：提交 `b641d2a` 中的 PRD v0.15 及其配套文档，修订结果为 [PRD v1.0](PRD.md)。评审依据是项目发起人历次明确要求，以及本次“评审后无问题即可转正式”的授权。

结论：修正下表中的歧义和文档矛盾后，未发现阻止本版本作为正式产品需求基线的未决核心行为。PRD v1.0 固定第一阶段范围、40 项 P0 与 3 项 P1 的边界及验收原则；相关技术、交互和运营参数按既定阶段门关闭。此结论是产品与文档评审，不是课程教研审校、软件测试或真实学习效果验收。

## 1 评审范围与修正

对照自主启动、理论与实践往返、持续学习、课程全景和证据图谱、两类账号、访客本地保存、登录承接与同步、教师授权和答案、Agent／Skill、真实执行与核验、失败恢复、交付运营逐项核对。功能需求与 [综合测试计划](TEST_PLAN.md) 中的 FR01–FR43 追踪对应。

| 编号 | 发现的问题 | 定版处理 | 状态 |
|---|---|---|---|
| R01 | 标题写“草案”，范围、优先级及下一步仍写“待评审”，无法表达已确认的产品范围 | 定为 v1.0 正式需求基线，修改范围与下一步，并加入需求变更规则 | 已关闭 |
| R02 | 已定的 Agent 职责和授权边界被与未定的 LangGraph、资源、收费方案一起称为“建议” | 分列产品要求与待决参数；固定四项学习职责＋按需设计职责，具体运行配置与技术留在 ADR | 已关闭 |
| R03 | “多语言”有候选清单但没有确定第一阶段最低语言范围 | 固定 C、C++、Java、Python、JavaScript 和独立 SQL 环境；精确版本、依赖和镜像在适配器验收前锁定 | 已关闭 |
| R04 | P1“教师课程视图”可能包含 P0 已要求的单个授权学生记录查看 | FR18 明确为跨学生的群体汇总／批量分析；个体记录按 FR12／FR35 在 P0 验收 | 已关闭 |
| R05 | 测试计划把全部图谱关系要求为无环，会错误拒绝概念或应用关联 | 无环要求限定于层级归属和必须满足的先修依赖；其他关系按类型检查 | 已关闭 |
| R06 | 完整课程仅按“声明范围”验收，需防止临时缩小范围绕过全课程门槛 | 先审完整范围与深度清单，再编制和验收；核心缺口不得因缺工具而静默排除，范围变更留记录 | 已关闭 |

## 2 定版后仍须关闭的阶段事项

以下事项保留在 PRD 第 12 节，没有被误记成已定或已完成：

- D01／D07：本人实测课程、目标和学习检查点，在开始个人持续学习测试前确定。
- D03／D04／D05：各目标证据标准的具体实例、权限控件及答案开放细节，在相应流程／原型定稿前落实。
- D08：认证、教师身份核实、附件存储及同步实现，在架构、数据库和接口契约定稿前确定。
- D02：编译器／解释器、依赖、镜像和专用环境，在对应适配器验收前锁定。
- D06：实际人力和排期在开发安排前落实；容量、预算和成本在公开试用前测量。
- D09：配额、数据保留、访客临时处理及删除时限，在开放外部试用前明示并验收。

这些事项有明确依赖门槛，不能在未关闭时批准其后续实现或外部试用。需求正式定版不意味着配套设计文档自动获得实现批准。

## 3 交付风险与后续工作

CS01–CS13 的完整默认课程内容、活动、核验和恢复均属于第一阶段。当前格式样例不能代替完整课程；必须落实课程范围审阅、内容编制、环境和标准审校的责任，并逐门形成覆盖及验收报告。本人学习一门课程不能代替其余课程验收，也不能作为学生群体效果证明。

后续依据正式 PRD 走查页面原型、锁定实施契约、编制全部课程内容并开发；测试与发布状态继续依据真实记录更新。范围或核心行为变化须更新 PRD 版本，以及受影响的 FR、流程、数据、课程和测试追踪。
