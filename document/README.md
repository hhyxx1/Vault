## 重建分支与旧版参考

从 2026 年 10 月 2 日起，`hyx_dev` 清除旧版前端、后端、运行数据与 Docker 部署配置，保留新版 `document/` 文档和通用 Git 忽略规则，从需求重新实现。此时尚无可运行的新版应用，不沿用旧部署命令。

旧版代码保留在 `main`，清理前已核对其应用代码与 `hyx_dev` 的旧版一致；本次不修改 `main`。需要参考时可切换分支：

```powershell
git switch main
# 查阅旧版后返回新版开发分支
git switch hyx_dev
```

旧版本也可按提交 `b804549` 查阅，其中包含清理前的旧代码和新版需求文档。分支切换前先提交或保存手头改动，避免混入其他分支。代码参考不改变新版需求与设计的判断依据。

## 开发约定

- 项目开发目录：`C:\Project\Vault`。
- 新版开发分支：`hyx_dev`，远端：`mine`，仓库：<https://github.com/hhyxx1/Vault>。
- 从 2026 年 10 月 2 日起，本轮及后续授权工作产生的新增、修改和删除，以完整、可审查的改动单元提交并推送到 `mine/hyx_dev`。
- 提交前检查差异，只暂存当前任务产生的文件；不自动纳入既有未跟踪文件或他人的未提交工作。
- 凭据、学生个人数据、运行数据库和本地产物不写入版本历史。需要配置时提供变量说明和示例。
- 新增和更新的项目文档统一放在根目录 `document/`，文档图片放在 `document/assets/`。
- 教学 Skill 包属于应用内容与运行资源，其格式和运行位置在技术设计中确定；私人投稿和学习数据不直接进入项目 Git，项目说明文档仍统一放在 `document/`。
- 本次未迁移旧 `design_docs/`、`完成作品/` 等未跟踪内容。若需要统一归档，单独核对内容、用途和敏感信息后执行。
- 分支提交和推送不等于生产部署。服务器更新需作为独立任务完成发布验证。

## 接下来按此顺序推进

1. 对照默认方案建议评审 `PRD.md`，逐步选定本人持续学习课程与目标；教材可选，核对规则和实际资源。
2. 画理论与学生尝试交替展开的学习工作区及教师关键流程，明确实际结果如何改变教学，以及各类活动的验收标准。
3. 按新版需求细化表结构、同步接口、Agent 与 Skill 契约，明确课程、任务、证据、执行核验及失败恢复；现有代码不作为判断依据。
4. 按课程与语言矩阵编写开发清单和验收方案，再开始实现。
5. 对所有声明支持的课程逐门验收，同时开展本人一门课的持续学习测试；分别记录结果。
