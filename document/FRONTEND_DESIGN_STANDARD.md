# 前端设计与品质标准

版本：v1.1

更新日期：2026 年 10 月 3 日

状态：项目发起人明确要求的正式前端质量基线，对应 [PRD v1.3](PRD.md) 的 NFR-UI01。首个栈切片已有原创页面、八维修订和独立审阅；记录见 [当前品质复核](FRONTEND_QUALITY_REVIEW.md)，全部产品页面与发布状态仍需完整验收。

## 1 品质目标与适用范围

前端页面以 **Awwwards、Webby Awards、FWA 获奖级网站**为品质标准。完成后从**排版、留白、视觉层级、色彩、动效、微交互、响应式和原创性**八个维度自检并持续优化，直到没有明显可提升之处。

标准适用于全部交付页面、组件和适用状态：学生自主学习、教师支持、课程知识图谱、学习工作区、资料与 Skill、账号与同步，以及加载、空数据、错误和恢复体验。入口页、静态高保真图和演示动画不能代表全部前端通过验收。

研究获奖作品时，记录官方获奖页面、实际访问日期、适用场景、值得参考的处理和本项目的原创转化理由；选择与复杂内容、数据探索、长期使用和移动操作相关的作品。具体视觉方向在设计阶段确定。本项目的八维检查是项目验收规则，评审记录不得冒充奖项官方评审或获奖认定。

参考入口及依据：

- [Awwwards 获奖作品](https://www.awwwards.com/websites/sites_of_the_day/)：用于研究获奖作品的实际视觉和交互表现。
- [Webby Awards 官方评审标准](https://www.webbyawards.com/judging-criteria/)：涵盖内容、结构与导航、视觉设计、功能、交互、创新和整体体验。页面品质评审须同时考虑完整使用体验。
- [FWA 官方周年说明](https://thefwa.com/FWA25/25.html)：强调数字设计与开发中的创新，作为原创表达和交互完成度的研究依据。

## 2 页面与流程覆盖

页面和状态来源于 [用户流程与页面行为](USER_FLOWS.md)。每个页面单独登记 VQ-01–VQ-08 的结果，跨页连续操作同时走查 UF01–UF09。

| 页面范围 | 重点品质场景 |
|---|---|
| P00 学习入口、P02 目标确认 | 品牌表达、课程与问题入口、未知方向启动、目标编辑、确认和失败反馈 |
| P01 课程图谱、P06 课程与进度 | 层级与关系辨识、真实目标分母、四类证据状态、密集内容、搜索定位、展开和窄屏导航 |
| P03 学习工作区 | 理论、作品、真实结果和 Agent 辅导持续往返；长文、代码、公式、终端及面板切换 |
| P04 作品与核验、P05 证据详情 | 作品版本、标准、排队与执行、逐项核验、帮助、冲突、人工复核及下一步 |
| P07 资料与 Skill | 来源、上传与解析、版本、私人草案、试用、校核与分享范围 |
| P08 账号与同步 | 本地／账号空间、登录承接、同步进度、离线、附件失败、冲突、导出和账号切换 |
| P09 教师工作区 | 独立教学空间、课程与任务编辑、答案控制、授权内作品与反馈、撤权状态 |
| P10 教师课程编辑与资料 | 自建课、资料导入／解析、AI 草案、可见范围与学生预览、工具缺口、发布与撤回；权限和解析异常表达清晰 |

组件检查至少覆盖导航、按钮、表单、弹层、抽屉、标签／图例、列表／表格、提示与通知、编辑器／终端、图谱、上传、同步队列及空／错误状态。仅当该页面不含某一交互时可标“不适用”，须说明理由；不能因难以检查而跳过。

## 3 八维品质检查

八项分别通过，不能使用平均分掩盖短板。检查时同时写明做得好的依据、仍可提升之处及修订结果。

| 检查 ID | 维度 | 必须达到的表现 | 检查方式与证据 |
|---|---|---|---|
| VQ-01 | 排版 | 字体、字号、字重、行高和行长形成一致体系；中文长文、英文术语、公式、代码、数值与表格层次清晰；长标题和字体加载后仍稳定可读 | 逐页检查真实长内容和字体回退，保存正文／代码／公式／表格截图；核对跨页文字规格与截断规则 |
| VQ-02 | 留白 | 间距、网格、对齐与分组一致；密集工作区仍能区分任务、作品、结果和辅导；空白与内容密度有明确取舍，重点区域获得足够空间 | 检查空内容、少内容和密集内容，核对组件内外间距与跨页节奏；记录拥挤、割裂或无目的空白并修正 |
| VQ-03 | 视觉层级 | 用户能辨认所在课程、当前目标、主要动作、真实结果和下一步；标题、辅助信息、来源与告警各有稳定层级；次要控件不会抢夺学习注意力 | 从入口和直接打开详情两种路径实际操作；检查多任务、多告警和长内容下的优先级与扫描顺序 |
| VQ-04 | 色彩 | 品牌、背景、文字、交互与语义色形成一致体系；学习状态和工具状态含义稳定，以文字／图标辅助；渐变、透明和图谱背景上仍保持对比 | 保存色彩与状态映射，工具测量对比度；检查四类目标状态、关系图例、未核验、工具失败和离线状态，不能只靠颜色辨别 |
| VQ-05 | 动效 | 转场、展开、状态更新与反馈具有明确目的，节奏协调、连续流畅；图谱更新保留当前位置和选择；支持减少动态效果，操作和内容仍完整 | 在实际浏览器录制转场、图谱更新与加载过程；检查打断／重复操作、低性能条件、减少动态效果及焦点保持 |
| VQ-06 | 微交互 | 悬浮、焦点、按下、禁用、选择、拖动、提交、取消、保存和恢复都有恰当反馈；键盘／鼠标／触摸语义一致，异步进度显示真实状态 | 按完整流程操作，覆盖成功、排队、失败、重试与重复点击；记录焦点、反馈、事件和实际状态，纠正延迟或误导提示 |
| VQ-07 | 响应式 | 手机、平板、笔记本与宽屏均有经过设计的布局；按学习任务重组面板，信息、动作和上下文不丢失；图谱提供等价树／列表入口 | 按第 5 节矩阵截图和实际操作，连续改变宽度并检查旋转、长内容、缩放和触摸；记录遮挡、溢出、错位和操作缺口 |
| VQ-08 | 原创性 | 建立穹隆自己的视觉概念、课程探索与学习表达；字体、色彩、图谱、组件和动效共同支持该概念，跨页保持一致且完成度高 | 记录视觉概念、参考来源、独立设计取舍和组件样例；由独立审阅者比较表达是否有辨识度、与计算机学习任务契合及跨页一致 |

色彩底线采用 W3C 的 [文字对比度规则](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字至少 4.5:1，大号文字至少 3:1；关键控件和传达含义的图形按 [非文本对比度规则](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) 至少 3:1，例外按相应规则判定并记录。键盘可用、可见焦点和状态文字仍属于既有产品要求；达到对比度数值不自动代表视觉品质通过。

## 4 学习产品必须保持的表达

- 当前活动的目标、理论、学生作品、实际结果与辅导有稳定关联，切换面板后继续编辑和观察，不丢上下文。
- 图谱的关系类型、方向、来源、目标分母和状态原因可理解；动态变化源于真实证据，更新与展示操作分别处理。
- 运行成功、正确性核验、独立达标证据、部分满足、需巩固和未评估明确区分；动画、庆祝或进度条不能将其混为同一结论。
- 学生自学与教师发布任务的答案规则清晰，授权和私人内容边界通过相应状态表达。
- 本地保存、账号关联、待同步、云端已保存、失败与冲突分别显示真实状态；过程反馈保留恢复入口。
- 动效和装饰支持阅读、操作和理解。页面不能要求用户等待装饰动画结束才能学习，不能打断编辑、抢占焦点或遮盖真实错误。

视觉修订涉及以上行为时，必须同时回归相关 TC 用例；品质评审不能替代功能、权限、真实性和数据恢复验收。

## 5 状态、内容与设备检查矩阵

每个页面登记其适用状态：初始／空数据、加载、等待学生、排队／执行、完成、失败／重试、取消、离线、权限受限、内容过期、同步冲突和恢复。使用中文长标题、长段落、公式、长代码行、复杂表格、大量图谱节点及多条错误等内容检查。测试或演示数据明确标注，不写入真实学习档案。

默认视口至少检查 360、390、768、1024、1440、1920 CSS px，并连续改变宽度核对断点附近与中间宽度；补充 320 CSS px 窄屏、手机横屏和 200% 浏览器缩放。代码／终端／大表格／图谱等二维内容可在所属区域明确滚动或切换等价视图，页面导航、说明和主要操作不能因此不可达。

浏览器和设备矩阵在实现前登记，记录实际版本、操作系统、视口和输入方式；覆盖目标支持范围的桌面与移动环境、鼠标／键盘／触摸、常规与减少动态效果。能用模拟视口检查的布局和需要真机／对应浏览器验证的交互分别记录；未验证的环境不能标通过。性能检查沿用 QT-04，记录具体设备、内容量、实际表现和问题，不能仅在高性能开发机上判断流畅。

## 6 设计、实现与持续优化流程

1. **视觉研究与方向**：研究获奖作品，建立原创视觉概念和取舍记录，说明如何支持计算机专业学生的理论与实践学习。
2. **高保真设计与状态规格**：基于 P00–P10／UF01–UF09，形成统一文字、间距、色彩、图标、组件和动效规则；覆盖关键页面和适用状态，保持完整功能入口。
3. **实际页面实现**：在浏览器中完成页面与交互，对齐真实功能状态。模拟流程明确标注，不能伪称端到端闭环已经实现。
4. **八维逐页自检**：结合截图与实际操作检查全部维度，记录明显可提升项、预期效果及修订优先级；不能因为页面已可用就停止品质检查。
5. **修正与回归**：逐项优化；复查修改页面、共享组件、相邻流程和受影响的功能／性能，保留修改前后证据。
6. **独立复核**：由未参与该轮实现的审阅者或独立审阅 Agent，查看实际页面和检查证据；静态证据不能覆盖的交互须实际验证。复核发现明显可提升项则回到第 4–5 步。
7. **完成记录**：全部交付页面、适用状态和设备范围完成八维检查，明显可提升项全部修正并复核后，才能记录前端品质通过。发现新问题则重开记录并继续优化，不把一次通过作为永久结论。

持续优化不预设固定轮数。完成判定须有页面／状态／设备覆盖、各维度结果、实际验证与独立复核作为依据，不得用实施者“感觉不错”、自动分数或未复核的截图宣布没有明显可提升之处。

## 7 评审与完成记录

实际设计／实现阶段建立 `document/FRONTEND_QUALITY_REVIEW.md`，公开测试截图和录像放在 `document/assets/`；私人作品及账号信息不进入 Git。当前尚未创建执行记录，不能预填“已通过”。

| 记录字段 | 内容 |
|---|---|
| 版本与范围 | commit、构建版本、页面 ID、流程、组件、状态、浏览器／设备／视口及检查日期 |
| 设计依据 | 原创视觉概念、获奖参考官方页面、参考用途和独立转化理由 |
| 八维结果 | VQ-01–VQ-08 各自的检查内容、截图／操作证据、通过／失败／待测／不适用及理由 |
| 问题与修订 | 问题 ID、具体位置、复现步骤、明显可提升之处、修改前后、受影响回归结果 |
| 独立复核 | 审阅人／Agent、所查看版本、实际操作与证据、仍待修正问题及关闭确认 |
| 最终结论 | 覆盖范围、八维通过情况、没有明显待提升项的复核依据；未覆盖项不能宣称完成 |

本要求追踪为 NFR-UI01／QT-09／VQ-01–VQ-08；与 QT-06 的访问性和响应式、QT-04 的性能、TC-01–TC-46 的功能测试共同构成前端交付门。此品质标准不改变第一阶段 13 门完整课程、学生自主学习、教师端和多 Agent／Skill 的既定范围。
