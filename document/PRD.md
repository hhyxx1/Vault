## 1 文档目的

为新版项目确定产品方向、第一阶段范围和可核对的验收条件。新版主要面向计算机专业学生，以主动自学、自我了解和持续学习为核心，保留教师端与多 Agent 协作。本版本固定产品行为、范围与验收基线；流程、数据和技术文档负责落实交互与实现，不能静默改变本基线。

本文件优先反映项目发起人的明确要求。新版从需求重新设计和实现，现有代码不作为角色、Skill 或架构选择的判断依据；旧计划书不能直接作为新版需求或成果证明。

本文定义的产品能力与验收条件独立于具体实现。第三方项目仅用于分模块的设计研究；是否采用其代码、组件或技术栈在后续架构评审中决定。研究资料与产品需求分别组织，不能将参考项目的能力写成本项目已实现的成果。

## 2 事实与决策状态

### 2.1 已确认要求

- 主要群体为计算机专业学生。
- 学生可以主动学习、了解自身情况并持续推进学习目标。
- 学生需要看清整门课程的内容范围、哪些目标已有达标证据，以及还有哪些内容需要学习、巩固或核验。
- 课程内容和个人学习状态通过可交互的动态知识图谱直观展示，能够从节点进入具体学习。
- 学习过程以理论与实践结合为核心，围绕学生实际思考、操作和反馈持续教学；不采用观看完整课程后再统一练习的默认体验。
- 保留多 Agent，并要求角色协作对学习过程产生实际价值。
- 保留教师端，教师能够支持学生学习。
- 教师可以创建预设 13 门之外的独立课程，上传自己的教学大纲、PPT 和资料，由 AI 辅助建立课程。
- 教师可选择资料是否对学生可见；学生提问时，RAG 仅使用明确设为学生可见且当前有权访问的资料内容，私有资料的索引切片不得提供给学生。
- 学生和教师采用两类明确的账号，各自数据分别存储、管理和授权。
- 不登录也可以学习；未登录的学习数据只在浏览器／客户端本地持久保存。
- 登录后可将本地学习数据关联并同步到本人账号，继续学习和跨设备使用。
- 登录后的学生可以关联教师，教师访问范围需明确。
- 学生不依赖教师先出题、发布问卷或组织测评才能获得学习诊断和继续学习。
- 自主学习任务由学生自主查看答案；教师发布任务的答案可见性由发布教师控制，关联教师不限制学生其他自学任务。
- 项目发起人明确重新设计与开发，现有代码不作为新版产品判断依据。
- 目标包含可推广产品的交付和运营。
- 项目目前尚未开展真实投入使用的测试，没有可引用的真实学习效果数据。
- 初期由项目发起人本人真实学习一门计算机专业课程进行测试，具体课程尚未确定。
- 产品应支持常见计算机专业课程的持续学习，支持范围不由个人自测选用的课程限定。
- 每门声明支持的课程都需要分别验证，个人选一门课持续学习不替代其他课程验收。
- 增加在线多语言编译、运行及结果核验能力，作为编程与实验活动的工具。
- 前端页面以 Awwwards、Webby Awards、FWA 获奖级网站为品质标准；完成后从排版、留白、视觉层级、色彩、动效、微交互、响应式和原创性八个维度自检并持续优化，直到没有明显可提升之处。

### 2.2 纳入需求基线的产品方案

- 建立适用于 CS01–CS13 的共同学习与证据流程；项目发起人可沿本人实际选定的课程持续学习验证。
- 用课程支持矩阵核对各课程的活动、核验和恢复能力；逐步记录知识单元及实验类型的验收范围。
- 学生以目标、当前问题或实作任务开始，逐步建立能力证据。
- 学生先确认可修改的短期目标；不确定方向时，可确认一个临时探索目标。
- 路线保留课程知识结构与先修，每个单元让必要理论、学生尝试、实际反馈和解释交替展开；根据表现选择补充、修改或新条件应用。
- 各课程共用学习与证据流程，每个活动声明学生动作、产物、核验依据、帮助归属、恢复及下一步；环境和检查器按活动类型适配。
- 网络课程提供浏览器可访问的受控实验工作台，真实配置网络并保存过程与结果证据；具体托管和隔离实现由架构决策确定。
- 教师第一阶段提供课程材料、知识结构、任务和标准审核等支持功能。
- Agent 按需要协作，共享结构化学习证据，保留可追溯的交接记录。
- 保留并重新设计多 Skill 自动生成、选择和组合能力；教师与学生均可创建或导入自己的教学 Skill，按权限和版本使用。
- 明确四项学习职责，并设置按需调用的课程与 Skill 设计职责；核验与内容发布保持独立检查。
- 初期以任务表现、帮助程度和验证结果描述状态，不展示未经校准的精确掌握概率。
- 提供固定版本课程全景及目标证据概览，按章节／知识单元展示达标、部分满足、需巩固和未评估；目标计数与占比不等于精确掌握概率。
- 账号认证与业务数据分离；学生和教师的角色资料、个人学习空间、教师业务空间及授权视图分别管理，认证服务与物理数据库方案由技术设计决定。
- 登录承接当前未绑定本地空间，关联归属与上传状态分别显示；同步可重试，账号切换不转移已有记录。
- 教师关联和数据共享分别处理；教师也可拥有自己的个人学习空间，不混入学生或教学数据。

本节方案继续纳入 v1.3 产品基线。实现选型和仍待测量或定稿的参数按第 2.3 节、第 12 节及配套设计文档处理；不得将建议参数写成已部署或已验收事实。改变本节确认的产品行为和第一阶段范围时，须通过需求变更记录更新本基线及相关 FR、流程、数据和测试追踪。

## 3 产品定位与价值

产品是面向计算机专业学生的多 Agent 辅助学习与教学系统。核心体验是学生围绕具体问题边理解、边尝试、边观察和修正；多个职责根据当前作品、推理和真实结果提供理论、示范、实践与下一步。明确目标、建立状态与核验理解用于支持这一持续教学过程。

学生需要能够回答：

1. 我希望达到什么目标，目前最值得先做什么？
2. 我已经能够独立完成哪些事情，哪些仍需要帮助或验证？
3. 我卡住的原因可能是什么，系统凭什么这样判断？
4. 我今天如何继续，上一次的进度如何恢复？
5. 学过之后是否能够在新任务中应用，隔一段时间是否还会？

计算机学习范围包括概念理解、数学与逻辑推理、代码阅读、算法分析、调试、编码、数据库操作、实验和项目实践。学生能够围绕整门课程建立目标和章节路线，按活动持续推进；课程支持不限定为某种语言的刷题工具。

自测先从具体知识单元开始，但产品应提供跨章节和跨会话的学习支持。常见课程的材料、任务和核验方式需分别适配，不能用同一类编程题替代全部课程内容。

### 3.1 教材与教学依据

教材、讲义、课程链接和学校大纲是可选参考，用于对齐章节、术语、符号、目标深度和资料出处。学生未提供资料时，系统仍应从课程名称、当前问题或目标启动，使用经核对的默认课程知识范围、先修关系、任务和核验标准，提出可修改的路线并开展教学。

默认课程结构及标准需有可检查依据和版本，属于内容维护工作；不能以模型自身知识或多个 Agent 一致赞同代替核对。新增或超出已核对范围的内容说明不确定项，避免写成已经验证。指定教材时可按目标调整章节和表述，不要求逐页推进，也不自动把教材习题答案当作唯一标准。

### 3.2 Agent、资料与 Skill

Agent 承担角色职责，资料提供教学内容与依据，Skill 是可复用的教学流程或方法包。一个角色可使用多个 Skill，同一个 Skill 也可由不同职责按需使用；新增 Skill 不必新增常驻角色。Skill 自动生成与教师、学生提供的能力纳入新版方案，使用、生成、试用、核验、发布与版本规则见 [教学 Skill 设计](SKILL_DESIGN.md)。

### 3.3 理论与实践交替的学习体验

每个知识单元建立概念／原理、适用条件、活动与表现的对应关系。学生通过当前问题理解学习目的，按需获得必要说明或示范，再亲自推演、构造、编码、配置或设计；实际现象引出进一步解释、修改和验证。顺序可以往返，不固定为先讲完整章再练习。

零基础可先了解概念和观看一段必要示范，不强制猜测尚未接触的知识。已有基础可先尝试再讨论，学生可主动请求理论、示例或按答案策略查看参考解。资料与视频作为可选参考，不以阅读完成、视频观看时长或固定讲解结束解锁实操。

实践后回扣定义、条件、关键推理和适用范围，再安排不同条件的应用。课程路线检查先修和重要理论是否遗漏；不能仅用几个项目步骤覆盖整门课程，也不把纯操作成功当作理解。理论课的实践可以是状态推演、证明、反例、建模和设计，无需全部转换为代码。

学习工作区围绕同一活动组织当前问题、作品／实验、实际结果、对应理论和 Agent 辅导，学生可持续编辑、运行和讨论。具体页面布局由用户流程设计落实；教学必须引用学生当前版本及结果；平常试验不要求每次操作确认或测评，阶段核验与自由探索分别处理。具体场景见 [学习闭环设计](LEARNING_LOOP_DESIGN.md)。

### 3.4 整门课程的内容与学习概览

默认课程蓝图明确完整声明范围、深度、章节／主题、知识单元、可检验目标与先修，区分核心与扩展选修。每个目标有稳定标识和必要表现标准，按目标要求核对理论解释、推演／操作、适用条件或新条件应用；教材仍可选。蓝图、内容和环境的具体清单待建设，不因已有课程名称或代表性活动就宣称完整覆盖。

学生可以查看整课、章节、知识单元及当前个人计划的概览，展开目标查看作品、核验条件、帮助、时间、不确定项和下一步。至少显示已有独立达标证据、部分条件满足／仍需帮助、已有证据显示需巩固和尚未有效评估四类；争议、工具故障、缺少环境和需要再检验另作原因或标记。状态由实际证据形成，未评估不计为不会。

可以显示“当前范围 N 个目标，其中 M 个已有达标证据”及 M/N 的目标达标占比，注明课程／规则版本、统计范围和证据来源。仅计稳定的可检验目标，不把题目数、章节父节点与重复引用加入分母；部分目标的一维通过不能平均抵消其必要维度的缺口。比例是目标证据统计，不是精确掌握概率、考试预测或剩余学习时间。

整课核心、扩展选修与个人计划范围分别统计，不能将完成几个个人目标显示成整门课程 100%。未支持核验的已定义目标仍保留在相应范围，注明限制；课程范围未完整定义时只标已定义范围，不称整课。完整蓝图与统计规则见 [课程支持矩阵](COURSE_SUPPORT.md) 和 [学习闭环设计](LEARNING_LOOP_DESIGN.md)。

已有基础的学生可直接核验相应目标，必要时补充新条件表现，无需先重复所有讲解与训练。后续冲突、标准修订与课程范围更新说明变化原因并保留历史；仅时间过去不能自动判为遗忘，尚未进行的延迟检查保持待检验。普通练习仍可以自由开展，不为每个细碎知识点强制考试。

动态图谱作为课程概览的主要导航，支持按课程、章节、知识单元和目标展开／收起、缩放、定位与选择；归属、先修及概念／应用关联分类型显示，连线可查看含义、方向和来源。父节点显示其范围内去重目标的状态分布与 M/N，目标节点显示具体证据摘要；父节点不是额外的可检验目标，先修连线也不传递达标结论。选中后查看目标条件、作品、核验与帮助，并进入原理回顾、实践或直接核验。具体交互见 [学习闭环设计](LEARNING_LOOP_DESIGN.md#62-动态知识图谱与学习导航)。

动态变化由有效核验、证据同步／删除、课程或标准版本变化触发，只影响实际适用的目标，再重算父节点统计；更新说明依据并保留当前选择与视图位置。点击、拖动、阅读、展开和过滤仅改变展示，不改变达标状态或整课统计分母。状态同时用文字与颜色表达，提供等价的键盘可用列表／树形视图；教师看到的个人状态和证据仍受学生授权约束。演示数据与模拟核验明确标注，不写入真实学习档案。

### 3.5 教师自建课程与资料辅助

CS01–CS13 是平台负责完整建设和逐门验收的默认课程基线，不是课程创建的数量或名称上限。教师可建立其他计算机专业课程，采用独立课程标识、范围、蓝图、图谱、活动、核验标准与发布版本；来源标为教师自建，学习状态按该课程确认的目标集合统计，不混入默认课程的分母。

教师可从空白、允许复制的模板或自己的教学大纲／PPT／参考资料建立课程。第一阶段导入至少覆盖 PPT／PPTX、PDF、DOCX、TXT／Markdown；旧 PPT 使用受控转换，上传失败、扫描件、图片／公式或图表解析缺失须展示原因和待补项。AI 辅助提取结构、映射资料与目标、生成理论／活动／核验及 Skill 草案，教师可编辑并审阅；解析完成或 AI 生成成功不等于课程正确或完整。

上传资料默认教师私有。教师侧备课 AI 可在本人权限内参考私有资料；课程草案和派生摘要仍默认私有。发布前教师预览并明确选定学生可见的独立课程内容／资料版本，不能连带开放原始资料、私有引用、源切片或其他课程的权限。PPT 备注、隐藏页和嵌入附件默认不向学生提供；需要纳入时显式选择并预览。排除部分内容时建立经确认的学生副本，下载、解析与 RAG 使用该副本，不能通过原件下载绕过排除规则。

“学生可见”只在相应课程发布范围和有效访问权限内生效，不意味着互联网公开，也不授予教师读取学生私人记录的权限。学生问答的检索、排序、切片加载、Agent 输入、引用、摘要、缓存和交接都必须执行该边界；隐藏出处而继续使用私有切片同样不允许。资料可见性与教师任务答案规则共同校验，可见资料不能提前提供尚未开放的任务答案；受控答案的切片、资料和派生产物保留原发布实例／策略关联，无任务问答、另一任务或下载也须校验该关联；不以学生改称自学取消限制，同时不扩大到无关联的其他自学内容。发布检查发现冲突时提示并要求调整。

教师自建课程经教师内容审阅、结构／权限检查和逐活动能力检查后可在明确范围发布，平台官方收录和完整支持验收另行记录。已有工具可复用；缺少环境或自动核验时明示外部实践、作品提交、人工复核或待适配，待适配目标保留在图谱和分母中并明确不可执行／待核验；已经开放的活动必须有实际实践、提交及核验／人工复核路径，不删目标伪称完整支持。复制课程不复制学生证据或他人私人资料，不自动扩大资料可见范围。更新或撤回保留版本和历史证据；撤回后停止后续访问，已经合法看到或下载的内容不能保证收回。原资料撤回不自动撤回经明确审阅独立发布的课程内容；界面列出相关发布物，可同时选择撤回，发布物自身授权与受控答案规则继续生效。流程见 [用户流程](USER_FLOWS.md)，权限与切片设计见 [资料解析与 RAG 权限设计](RAG_AND_RESOURCE_DESIGN.md)。

## 4 用户角色

| 角色 | 主要需求 | 职责边界 |
|---|---|---|
| 未登录学习者 | 直接开始、保存本地作品与进度、以后关联账号 | 不建立长期云端学习档案；关联教师与云端同步需登录 |
| 学生 | 自主开始、获取支持、完成任务、查看证据、持续学习 | 控制自己的目标、节奏和求助方式；能够反馈不合理判断 |
| 教师 | 提供课程内容、目标和标准，审核任务，必要时指导 | 只查看经授权的课程和学生信息；不成为学生自主学习的启动条件 |
| 内容维护者 | 维护知识关系、任务和验证标准 | 发布经过核验的内容版本，处理有问题的内容 |
| 管理者 | 管理运行配置、权限、部署和故障 | 保障交付运营；访问学习内容的权限按实际职责划分 |

学生和教师为两类账号，资料、数据归属、权限和管理入口分别明确。内容维护者和管理者为另外授予的职责权限，初期可以与教师支持工作由少量人员承担。教师可以在独立个人学习空间自学，不能因此读取其他学习者记录。

## 5 核心场景

### S01 学生独立开始

学生尚未登录、未加入班级，也没有教师发布的任务，仍可选择或描述目标，提交现有基础、当前代码或问题，获得起步任务，并开始一次学习。作品、进度和证据保存到当前浏览器／客户端本地空间；在线工具可临时处理本次请求，不形成长期访客学习档案。

未上传教材、未填写课程链接同样可以开始。系统使用经核对的默认课程范围协商目标；已有教材或学校大纲时，提供可选的对齐入口。

没有能力证据时显示未知和待验证，不能把自评问卷或一次对话直接转换成确定的能力结论。

#### 首次目标协商方案

学生可以从三类入口开始：已有想学的方向、眼前的代码或问题、尚不确定想学什么。系统先区分学生意图、任务要求和已有能力证据，再提出范围较小、可检查结果的目标草案。

流程为：表达意图 → 必要澄清 → 提出短期目标和完成依据 → 学生确认或修改 → 起步任务 → 根据新证据调整建议。方向、范围和结果存在实质歧义时才澄清，不要求学生先填写完整画像或一次决定整个学期。

目标草案至少包含想完成什么、对应能力、范围、完成依据和时间偏好。系统展示学生声明的已有基础与仍待验证的部分。学生确认前不能把草案写成已经接受的正式目标，模型也不能替学生回答确认问题。

例如，学生说“想学数据结构”，候选短期目标可以是“独立用栈实现括号匹配，并解释错误输入的处理”。完成依据包括代码、边界输入和解释；先用一个读代码或改错任务了解起点，再决定是否补充栈的基本操作。这个例子不代表首版已选定数据结构课程。

不确定方向的学生可以选择一项探索活动，确认的临时目标是“体验一类任务并判断是否继续”。探索结束再协商后续目标，不自动判定职业方向、兴趣或能力。确认目标与接受系统能力判断是不同动作。

上述流程为产品要求，具体页面布局和状态在用户流程与原型中落实。

### S02 学生遇到困难并获得帮助

学生在概念、推理或实作中卡住。系统结合当前任务和已授权材料，提出有依据的解释或候选原因，提供不同程度的帮助，并让学生继续操作、作答或解释。

记录提供了什么帮助及学生随后完成了什么。接受提示后完成原任务不自动成为独立掌握的证据。

自主学习任务可主动查看参考答案；教师发布任务按其开放规则执行。规则在开始任务前展示。未开放完整答案时，仍提供教师允许范围内的概念解释、错误反馈和提示；示范、代码补全、推导及连续提示不得变相交付整题答案。实际揭示仍记录帮助，不能因符合开放规则就认定独立完成。

### S03 学生核验并调整路线

系统在尝试过程中反馈实际结果，学生可修改、再运行和继续讨论；完成有意义的阶段后，通过新变体、解释或实践结果核验理解。证据不足或冲突时，明确说明需要补充验证；必要时调整后续任务，保留变化原因。日常反馈不把每次操作变成考试。

### S04 学生持续学习

未登录学习者重新打开同一浏览器／客户端，可从本地空间继续；登录账号则恢复本人空间中已同步的数据和本机待同步修改。系统结合目标、时间和新证据提供下一步，必要时安排复习。学生可以暂停、改变目标和调整节奏。

学生查看课程全景与证据概览，知道完整范围、当前目标分布、具体薄弱或未知项；从一个目标进入继续学习、查看依据或直接核验已有基础。个人计划完成不等于整课完成，平台缺少核验能力不算学生能力不足。

### S05 教师支持学习

教师维护课程资料、学习目标、知识关系、任务和核验标准，审核 AI 内容。在授权范围内查看学习证据，提供反馈或纠正判断。学生自主学习场景仍可运行。

教师发布任务时设置该发布实例的答案开放规则。推荐初版选项为随时可查看、有效提交后、指定时间后、手动开放；教师在发布前明确选择，学生看到条件和提示范围。规则变更保留版本、生效范围和时间，答案获取按有效策略重新校验；已揭示的内容无法真正收回，历史帮助和当时适用规则不能删除或回溯改写。

### S06 在线编译、运行和核验

学生在当前学习任务中选择语言和运行环境，编辑代码、提供输入，查看真实编译或运行输出，并根据反馈修改和重试。核验操作使用明确的测试集或检查规则，保存每次代码、环境和结果版本。

没有可靠核验依据时，结果显示“运行成功，尚未核验”。编译成功、运行成功、测试通过、独立完成与掌握判断分别处理。理论、证明和设计任务使用对应评价方式，不强制转换为可编译代码。

### S07 网络课程动手实操

学生从课程任务启动隔离实验，在浏览器查看拓扑、操作节点终端、修改配置、观察报文并提交检查。基础通用协议实验不要求学生先安装厂商模拟软件。实验范围与节点能力明确，厂商专有命令或设备行为需要对应环境，不能由通用节点假装实现。

系统自动保存拓扑与配置版本、可采集的操作事件、终端回放、关键状态快照、定向抓包和检查结果，并关联任务、提示和学生解释。学生返回后恢复任务与配置，再检查重建的网络；不承诺恢复原来的 TCP 连接等瞬时状态。

### S08 登录承接本地学习

学习者已在未登录状态完成若干活动。通过说明承接范围的登录入口，认证成功后自动将当前未绑定本地空间关联到实际登录账号，再后台分批同步课程、作品、尝试和证据。关联成功但上传未完成时显示待同步或部分完成，保留本地原件，允许继续学习和重试。

已有账号云端数据不被同名课程或较新客户端时间戳覆盖。教师登录承接自己的学习记录时进入个人学习空间。已属于账号 A 的本地缓存不因 B 登录而关联给 B；旧标签和迟到结果同样不能串号。

### S09 学生关联教师

登录学生接受邀请或申请关联教师／课程，界面展示教师身份及数据共享范围。学习数据仍归学生，教师通过授权视图查看相关课程、作品或证据并反馈；不自动开放其他私人历史。解除或撤销后停止后续访问与共享，学生自己的记录继续保留。

推荐两条默认路径：教师定向邀请、学生看清范围后接受即生效；学生申请、教师接受后生效。两者都记录双方动作和学生授权，等待或拒绝不影响自主学习。授权说明覆盖的已有记录及之后同范围的新提交；未提交草稿、完整聊天和其他课程不自动共享。

## 6 第一阶段范围

本节与第 7 节共同构成正式第一阶段范围和优先级基线。P0 与全课程门槛均须满足后方可交付第一阶段；实现参数和发布测量按第 12 节规定的时点锁定。

### 6.1 必须形成的完整流程

选择课程／描述问题（资料可选） → 确认学习目标和路线 → 进入当前问题 →〔必要理论／示范 ↔ 学生尝试 ↔ 真实反馈与解释 ↔ 修改或改变条件〕→ 阶段核验与原理归纳 → 局部证据更新 → 下次继续或再检验。

括号内为可往返的学习循环，按学生基础和实际结果调整，不是固定讲授顺序。理论和实践从单元学习中交替发生；课程路线仍检查完整知识范围与先修。阅读、观看与讨论可以辅助学习，阶段依据是目标对应的学生表现，不能只凭材料完成行为推进理解状态。

自然语言证明、开放设计或未具备的实验不承诺全部自动评价。无法可靠判断时保持待核验，仍允许继续其他学习。跨课程活动契约、理论与操作如何互相解释及逐领域案例见 [真实学习与证据闭环设计](LEARNING_LOOP_DESIGN.md)。

开发可以先用相邻单元打通底层闭环，但这只是开发切片，不缩减第一阶段交付范围。第一阶段完成前，CS01–CS13 的完整课程内容、目标蓝图、适用活动、必要核验路径、证据与恢复流程均须按矩阵分别建设并验收；模块开发可并行，未完成课程只能标为建设中。全课程验收后才能宣称第一阶段达到 13 门课全量支持。项目发起人连续学习一门课程是额外的持续使用验证，不能代替逐门验收，也不能据此声称其他课程学习效果已验证。验收分工与记录见 [课程与多 Agent 验证方案](COURSE_VALIDATION_PLAN.md) 和 [综合测试计划](TEST_PLAN.md)。不能以页面上线、可聊天、能生成计划、单个章节或仅运行一段代码作为完整交付标准。

### 6.2 第一阶段优先能力

- 未登录本地学习空间、学生／教师两类账号、独立资料与基础角色权限。
- 本地数据登录关联、可靠同步、账号隔离与明确范围的教师关联。
- 目标与当前学习单元。
- 经核对的默认课程范围、可选资料对齐、可修改章节结构与跨单元进度。
- 完整声明范围的课程蓝图、可检验目标、章节／整课证据概览和当前计划的独立统计。
- 起步任务和已有材料输入。
- 带依据的局部状态判断。
- 同一活动内关联理论、作品、实际反馈和辅导，支持持续尝试、解释与修正，并保存帮助记录。
- 实际的多 Agent 交接和协作。
- Skill 的自动草案生成、适用选择、多 Skill 组合、师生创建／导入、私人试用和范围发布；第一版使用声明式包与平台已有工具。
- 结果核验、失败处理和状态修正。
- 多语言在线编译或解释执行、版本可见的运行环境与测试结果。
- 数据库课程的隔离 SQL 执行与结果比较。
- 网络课程的基础隔离拓扑、浏览器终端、自动检查和过程证据。
- 持久作品与进度、下次继续、简单复习和待检验任务入口，按实际安排记录延迟表现。
- 教师自建课程、上传大纲／PPT／资料、AI 辅助生成与审核、学生可见范围控制和反馈。
- 教师备课与学生问答分别取用授权资料；RAG 切片、引用和派生内容受资料可见性及任务答案规则约束。
- 基础运行配置、故障记录和可复现部署。

以上能力均属于第一阶段目标。课程内容编制、平台能力实现和实际验收可按依赖分批推进；阶段完成门须同时满足 13 门课程完整范围和本节其他 P0 能力，不因工程分片而把未完成课程算作已支持。

### 6.3 后续扩展候选

跨课程目标与项目路线、长期复习调度、班级协作、教师批量查看、已有代码仓库接入、更多语言和依赖、多用户实验工作区、扩展分享与组织交付。基础教师关联和范围授权在第一阶段实现；更复杂分享根据个人真实学习测试结果安排。

### 6.4 第一阶段暂缓

完整教务或 LMS 替代、复杂问卷平台、智能体市场、大规模院校私有化交付、全学科覆盖、自动认定抄袭或 AI 使用、没有证据支持的排名和能力评分。

### 6.5 常见课程与语言基线

常见课程的全量支持是第一阶段验收要求，包括程序设计基础、面向对象程序设计、数据结构、算法设计与分析、离散数学、计算机组成原理、操作系统、计算机网络、数据库、软件工程、编译原理、人工智能基础与机器学习基础。课程名称可以不同，需通过版本化蓝图说明完整范围、深度、知识单元、可检验目标和活动类型；不能只给章节目录、少数示例任务或课程聊天入口。

第一阶段中每门课的完整课程范围内，每个主要知识单元和目标都须有可追溯的理论依据、学生活动、适用核验或明确的人工复核方式、证据要求和下一步；涉及编程、推演、实验或设计的目标须使用相应活动类型。无教材启动和可选资料对齐均须可用。课程入口、通用聊天、代表性章节和一种代码任务不能单独计为整门课支持。课程内容可逐批审核发布，但第一阶段门槛要求 CS01–CS13 均完成全范围审阅与验收。

每门课的默认完整范围和深度须先形成带来源的版本化覆盖清单，经课程审阅后作为内容编制与验收基准。核心内容不能因缺工具、缺检查器或尚未编写而静默排除；改变已审范围按需求变更记录处理，不能在验收时缩小范围使不完整内容通过。

第一阶段在线代码环境至少支持 C、C++、Java、Python、JavaScript；SQL 通过独立数据库环境执行。具体编译器／解释器补丁、依赖和运行镜像按语言矩阵在相应适配器验收前锁定。人工智能与机器学习活动需明确数据集、依赖和可执行的基础实验，不只返回文字讲解。

完整硬件实验、系统内核修改、外部网络实验、大型模型训练和长期 Web 服务等需要专用实验环境，当前应明确能力边界与替代活动，不虚称通用执行器覆盖这些实验。课程基线验收见 [课程支持矩阵](COURSE_SUPPORT.md)。

## 8 多 Agent 产品要求

### 8.1 职责基线

第一阶段包含四项面向学习过程的职责，以及仅在需要时调用的课程与 Skill 设计职责。设计职责负责可复用课程与方法内容的草案，不参与每次学生辅导；核验与发布分别控制。这是职责划分，不要求五个常驻进程、五个不同模型或每次请求全部调用。编排框架与运行边界见 [默认方案建议](DECISION_RECOMMENDATIONS.md) 和 [架构决策记录](ARCHITECTURE_DECISIONS.md)，实现选型须通过相应原型验收后记录 ADR：

各职责为可分别调用、可检查交接的角色单元，拥有明确输入输出和受限工具能力。普通请求按需调用；共同使用同一模型可行。学习状态更新由业务服务依据证据和版本校验，角色不能仅靠生成内容写入已掌握状态。

| 职责 | 职责范围 | 可检查的交接结果 |
|---|---|---|
| 规划与诊断 | 理解目标，分析证据，安排任务，选择协作与补充验证 | 当前目标、下一步、理由、完成条件、证据引用与不确定项 |
| 辅导 | 依据当前作品与现象提供理论、提示和示范，再交回学生尝试 | 对应原理、触发依据、帮助程度和下一步动作 |
| 实践任务 | 选择或设计适合的任务、反例和项目步骤 | 任务要求、关联能力、测试和标准 |
| 核验 | 核验功能、解释和迁移结果 | 核验依据、冲突项和推进建议 |
| 课程与 Skill 设计 | 生成／修订课程结构和可复用教学 Skill，分析适配缺口 | 方法草案、适用目标、依据、输入输出、工具需求和试用案例；不得自行发布或认定掌握 |

### 8.2 协作约束

- 简单问题可以由单个角色处理，复杂度或证据冲突触发必要协作。
- 不要求每次请求调用所有角色，也不要求各角色使用不同模型。
- 角色共享经授权的结构化记录，避免各自维护互相矛盾的长期画像。
- 教师备课和学生问答使用不同权限上下文。设计角色可在教师权限内参考私有资料生成草案；转交学生学习职责前，只能携带已明确发布可见的内容，所有 Agent／Skill 均不能扩大资料权限。
- 交接注明任务和作品版本、证据来源、已提供的帮助、预期结果及缺失证据；模拟角色的发言不计入真实学生证据。
- Agent 提交建议和证据引用；数据服务校验后更新状态。
- 辅导、核验和进度推进分别处理：辅导角色不能凭对话自行写入已掌握或完成状态。
- 编译、运行、测试、检索和存储由工具完成，工具结果不得由模型编造。
- 多角色互相赞同不等于结果正确，需要核验标准和外部运行结果。
- 一次协作具有结束条件、调用预算、超时及失败状态。
- Skill 草案生成与核验分别调用，使用实际规则、工具和必要人工审阅；生成者的自述或另一角色赞同不是唯一校核依据。
- Skill 选择与组合记录版本、适用阶段和理由；师生 Skill 不改变任务来源、答案规则、资料授权、工具权限和预算。
- 学生看到统一学习流程，必要时可以了解关键判断来源，不强制在多个聊天窗口间切换。

必须满足的规则：

1. 提交作品与核验完成是不同状态，不能提前标记完成。
2. 运行失败、评分失败和学生做错分别记录。
3. 事实、模型推断和学生自评分开保存。
4. 一次错误推断不能不可追溯地覆盖全部历史。
5. 重复请求和重试不会重复记分或重复推进任务。
6. 内容修订后，旧尝试仍可知道当时使用的任务和标准。
7. 内容模板与每个学生的尝试、帮助和状态分开；恢复状态不能混入其他学生记录。
8. 聊天结束、任务完成、单元完成与掌握判断分别记录；同一作品通过核验也不自动证明迁移或长期保持。
9. 执行状态与答案核验状态分开；测试通过只说明满足本次已执行测试及条件。
10. 测试集和参考答案需有校核记录，模型同一次生成的题目、答案和测试不能互相作为唯一证明。
11. 产物满足规则、解释表现、帮助程度、迁移与延迟表现分别保存；外部帮助未观测部分不能自动推断为没有帮助。
12. 活动、作品或标准发生变化时不自动沿用旧通过结论；原证据保留，明确是否需重新核验。
13. 学习数据明确归属访客本地空间或实际账号；同步和教师关联不改变他人的所有权。
14. 已关联账号的本地数据不会退回公共访客状态；切换账号不重新认领，旧同步队列不向新账号提交。
15. 学习同步不修改账号类型、管理权限或分享授权，不把客户端自述升级为平台可信核验。
16. 并行修改保留版本和差异；尝试与帮助保留历史；删除和撤销向设备传播，旧修改不能静默复活。
17. 任务来源和发布权限由可信发布记录校验；客户端改标签、同步或复制关联实例不能解除原答案策略。教师控制自己发布任务，不扩大为控制学生所有自学或读取私人记录。

## 10 可靠性与交付要求

- 关键学习状态按归属恢复：访客从本地、账号从持久空间恢复。账号长任务可查询、重试和取消；访客远程任务为短期处理，到期或重启后按本地作品重建／重跑并说明限制。
- 学生代码使用独立隔离运行环境，限制编译与运行时间、内存、进程、文件和输出；默认关闭外网，不直接在业务应用进程中执行。
- 执行记录按模式保存：访客结果回到本地，远程资源限时清理；账号任务持久保存，可查询和取消。环境故障与作品错误分别展示，重试不重复推进。
- 编译器、解释器、依赖和数据集版本可追溯；特殊实验环境支持范围明确，不能用模拟输出代替真实运行结果。
- 恢复不仅恢复聊天，还需回到实际作品与待完成动作；进程、事务、瞬时连接和外部设备等不能恢复的内容明确说明，重建后重新检查。
- 网络实验运行于独立受控执行环境；实验节点通信与管理通道分离，不将宿主或容器管理权限交给学生。采集只面向本人实验，说明范围和保存方式。
- 资料来源可回到具体文档或任务版本；来源展示不等于答案已正确。
- 模型接入集中配置，不将真实密钥写入代码、文档或 Git。
- 学习内容和记录按模式持久保存，访客提供本地导出，账号提供云端备份与恢复；访客临时输入、输出和实验附件不进入长期学习存储、备份或完整请求日志，外部服务保留条件需核对。
- 本地或云端容量不足、附件失败和同步冲突须显示真实状态，不以后台上传请求发出代替保存成功；原件在确认成功前保留。
- 支持响应、等待和失败提示；响应时间目标依据原型测量制定，当前不虚设数字。
- 基础部署、升级和故障恢复可复现，不依赖容器内临时手工修改。
- 角色、课程和个人空间权限覆盖读取、检索、修改及 Agent 工具调用。

现有要求给出不可违背的可靠性与数据处理边界；响应时间、可用性、并发量、上传规模、恢复目标和调用预算须在原型容量测试中以环境、样本和测量方法记录，并形成首发目标及超限降级行为，不能无依据预设。上线前还需确定访客请求和附件在执行器、模型服务与观测日志中的处理及删除时限、账号数据导出／删除行为、本地和云端容量提示及备份恢复演练。详细指标归入技术设计与测试计划，涉及学生界面的行为保留在本需求。

### 10.1 前端设计与体验品质（NFR-UI01）

前端全部页面以 Awwwards、Webby Awards、FWA 获奖级网站为品质标准。该要求覆盖 P00–P10、UF01–UF09 的学生和教师流程、学习工作区、动态图谱及正常／异常／空数据状态，不能只以入口页或静态展示稿代表完成。

页面完成后必须分别检查排版、留白、视觉层级、色彩、动效、微交互、响应式和原创性；形成问题记录，持续修正、实际操作验证并复审，直到没有明显可提升之处。八项分别通过，不能以总分、单张截图或基本功能可用抵消某一维度的缺口。自检之后需由未参与该轮实现的审阅者／独立审阅 Agent 复核。

视觉表达须帮助学生理解理论、动手实践、查看真实反馈与继续学习，同时保持课程范围、证据状态、答案权限、本地保存与同步信息准确。页面设计不得以动画、色彩或装饰暗示没有证据的学习成果。具体八维检查项、状态与设备矩阵、优化循环和完成证据见 [前端设计与品质标准](FRONTEND_DESIGN_STANDARD.md)，测试追踪为 QT-09／VQ-01–VQ-08。

## 11 产品验证与运营假设

### 11.1 待收集指标

| 维度 | 拟观察内容 |
|---|---|
| 自主启动 | 首次进入是否能开始并完成有效任务，阻碍点是什么 |
| 持续学习 | 学生是否回来继续、是否能恢复上下文、在哪些环节退出 |
| 自我了解 | 学生能否理解判断依据，对自身后续表现的预估是否改善 |
| 学习结果 | 新情境与延迟任务的表现、求助后独立处理类似问题的能力 |
| 协作价值 | 多 Agent 与单 Agent 在相近任务和预算下的诊断、学习、等待和成本差异 |
| 运营成本 | 一个学习单元的调用、执行、内容维护及支持成本 |

没有真实结果前，不填写留存率、提分率、诊断准确率或付费率等成果数字。聊天次数和签到仅为行为记录，不能替代学习效果。

### 11.2 个人真实学习测试

初期由项目发起人本人选择一门计算机专业课程，按真实学习目标、课程资料和实际进度使用系统。具体课程目前尚未确定。先核对相邻知识单元的完整流程，再持续学习后续章节，记录作品、提示、独立核验、学习恢复和产品问题，不以临时点击演示替代真实学习。

同时对课程矩阵和语言矩阵做功能验收。个人选用一门课不缩减系统的课程范围；本人完成某些单元或整门课程，也不能替代其他课程的验收或学生群体的效果验证。具体过程与记录模板见 [个人真实学习测试方案](SELF_STUDY_TEST_PLAN.md)。

### 11.3 收费与后续验证

默认建议采用基础记录管理和有容量的账号同步免费、在线资源有限试用，以及一档包含辅导反馈与实验额度的个人月订阅。内部 Agent 交接不分项收费，平台故障不重复扣正常使用额度；高资源任务提前说明，不默认自动超额消费。教师支持与组织交付后续按实际范围设计。

订阅结束回到免费方案，已有成果继续可查看、导出和删除，不因到期自动删除作品。超过免费云端容量时限制新增上传，说明范围并保留本地修改；本地学习仍可继续。具体保留政策与容量在上线前明示，不能用订阅到期静默清理学习成果。

模式尚未正式选定或上线。先通过真实学习测调用、执行、存储、内容维护与支持成本，再验证付费意愿和确定金额，不提前填写收入、毛利或收费效果。具体建议见 [默认方案建议](DECISION_RECOMMENDATIONS.md)。
