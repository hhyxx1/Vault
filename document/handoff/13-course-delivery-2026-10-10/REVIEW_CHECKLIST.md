# 交回 Codex 的复核材料与检查清单

执行 AI 完成后生成 `document/handoff/EXECUTOR_FINAL_REPORT.md`。若额度或上下文提前不足，保存 `EXECUTOR_PROGRESS.md`，明确尚未完成；不能输出虚假完整报告。

## 1. 交付报告固定内容

1. 实际工作tree、HEAD、远端提交、未提交/未跟踪文件及归属。
2. 13课各自当前版本、目标总数、完整内容数、可实践数、有实际可靠核验路径数、Q0–Q5各门状态、阻断项。以同一核心目标集合去重；不只列一个百分比。
3. 122模块台账逐行状态与证据链接；新增模块的来源、必要性和分母变化。
4. 每个新工具适配器实际能做什么、环境/资源版本、如何准备/运行/取消/清理/恢复。
5. 内容主张与来源账本、许可、冲突处理、未审校项；明确AI核对和专业签署的不同。
6. 每类活动的正确/替代解、至少两类错误、边界、证据不足、独立条件、工具故障、恢复及权限测试。
7. 测试命令、环境、原始结果、通过/失败/跳过原因和工件路径；未执行的一律写未执行。
8. UI设计稿对照截图，13课图谱六场景、设备/输入方式、八维问题与修正。
9. 教师/学生/游客、自建课程、资料RAG、答案、模型、Agent与Skill的实际路径及未通过边界。
10. 数据迁移、旧版本作品、撤回/回滚、备份恢复、服务运行位置和待补外部条件。

## 2. 必查错误模式

- [ ] 没有把 `full_course_available=true` 或调整分母作为完成手段。
- [ ] 122模块/366初始目标没有被静默删减；一个综合任务不冒充所有模块。
- [ ] 所有目标的必要条件有真实承载活动，非代码学科无需强迫写代码。
- [ ] 没有将返回预置字符串、模拟终端或伪造pcap当真实实操。
- [ ] 检查器能接受合理替代解、检出硬编码/遗漏边界等错误，预期独立核对。
- [ ] 有限表、有限测试、数值模拟与一般证明的结论边界正确。
- [ ] 解释不靠字数/非空/关键词通过；无真实审阅人没有虚构排队服务。
- [ ] 看答案/受帮助后完成没有直接标独立掌握，新实例有独立帮助记录。
- [ ] 失败/取消/超时/环境错误分开，旧成功和新反例都留痕。
- [ ] 本地、登录承接、账号切换、跨设备、冲突、撤销和导出涵盖所有活动类型。
- [ ] API结果绑定真实版本、工件hash与身份，迟到事件不能回写另一个账号。
- [ ] 客户端恢复结果不自动升级为权威证据。
- [ ] 教师隐私资料、受限答案不进入学生RAG、缓存或模型上下文。
- [ ] 自建课程能够复用工具，不以13个课程编号硬编码能力。
- [ ] 多模型为实际协议适配，真实调用与mock测试明确区分。
- [ ] 上传/生成教学Skill不能改ACL、提权、覆盖检查器或执行宿主命令。
- [ ] 图谱全景/局部/列表分母一致，无假边、无邻接掌握传播，状态因果可追溯。
- [ ] 同尺寸截图对照设计稿；动效可打断，键盘和减少动态效果可用。
- [ ] 没有泄露凭据、提交用户数据、删除其他项目、强推或擅改生产服务器。
- [ ] CI和本地结果相符，平台跳过项有真实补测或明确未测。

## 3. Codex 复核建议顺序

先审Git diff、迁移/权限/执行边界，再审新增核验器正确性与反例；从每种活动类型各选一条真实失败→修正→新条件→恢复路径。随后核对逐课覆盖和来源主张，抽取薄弱模块做深度复核，并检查全目标覆盖报告。共享机制有问题时扩大到所有使用课程，不以抽查替代执行方的全目标验收。

最后对照真实UI与设计稿、版本迁移、发布回滚及真实模型/专业审校门。发现缺口重开具体模块/条件，不笼统写“13课还不完整”，也不为了结束把未通过门改为通过。
