# 13 门课程完整开发执行方案

日期：2026-10-10。执行对象：可读写本机并运行工具的开发 AI。先读本文，再每次只展开一个模块和它依赖的公共能力。

## 1. 最终产品与不能改变的约束

学生可直接选一门完整计算机专业课程，也可建立 13 门之外的个人课程；教师可从自己的大纲、PPT、资料建立课程。教材是可选来源，不是开始学习的前提。所有课程都要支持理论与实践往返：确认目标 → 预测/尝试 → 保存作品 → 实际执行或推演 → 定位差异 → 解释原理 → 修改重试 → 新条件验证 → 记录证据 → 图谱呈现缺口 → 继续下一步。

- 保留学生端、教师端、四项学习 Agent 职责、按需课程/Skill 设计和多模型配置。不能收缩为课程播放器、题库或单聊天窗口。
- 未登录主要学习数据只持久保存在本机；临时在线核验遵循游客租约。登录后按已有确认归属流程承接本地数据，并可关联教师。学生和教师账号分类型管理，数据按所有者和授权隔离。
- 自学学生可自主查看答案；教师任务按教师设置控制。帮助记录、看答案记录与后续独立尝试分开。
- 师生均可提供资料和教学 Skill。教师资料仅在学生可见时进入学生 RAG 检索和引用；前端隐藏不是权限控制。
- 开源版允许用户配置模型供应商、兼容端点、模型与能力分工；不能只绑定 DeepSeek。密钥不进入浏览器包、Git、日志或公开课程包。
- UI 和知识图谱继续严格参照 `document/prototypes/knowledge-atlas/`，包括层级、密度、局部关系、证据面板、移动布局和过渡。示例数据不能进入学生真实进度。
- 说明和测试报告都放 `document/`；运行代码、课程内容和测试放各自已有目录。不要新建第二套产品、框架或重复数据库。

上位文档依次为用户已确认要求、`PRD.md`、`course-construction/CONFIRMED_DECISIONS.md`、技术 ADR 与各专项设计。本方案补充实施细节，不静默修改正式需求。发现文档冲突，记录具体条款与实际代码，再作最小范围修订；有实质产品取舍才问用户。

## 5. 公共工程工作包

### C01：数据驱动课程包和发布

现有落点：`content/courses/scope-catalog.json`、`services/backend/src/vault_backend/course_packages.py`、`content.py`、`apps/web/src/domain/course-packages.ts`。

保留稳定课程/目标 ID；内容、活动、标准、检查器分别版本化。新增版本归档旧版本而非覆写；已有记录按旧版本打开。一个目标可以有多个活动，一个活动可以覆盖多个目标的特定条件。查找不能只拿第一个 activity 代表全部目标条件。

统一注册按 `activity.kind`、工具 profile、受信 check id 分发。新增类型要同时接 schema、API union、结果 union、本地表/升级、同步类型/约束、图谱、证据页、导出、后台任务及所有受影响测试。参考 CS05 原生代数这一纵向实现，但抽共用生命周期，不复制 13 套账号和租约逻辑。

做一个不叫 CS01–CS13 的合成课程，使用 code、trace/native、sql 等已具备的注册工具，验证能力不是由课程编号或固定 UUID 白名单控制。教师上传的是受校验配置和模板引用，不能变成上传任意后端评分 Python 的入口。

### C02：语义核验替代单一固定 stdout

现有代码固定条件注册在 `course_checks/generic_rules.py`，能够硬编码输出的成功只表示本次固定条件。不要通过增加固定字符串就宣称算法掌握。

在隔离 worker 中运行多输入测试；受信检查器在学生无法改写的边界判断结果、状态、不变量、资源条件。每个检查器先有独立 oracle、小规模枚举或官方语义核对，再接受替代正确解和至少两类有意义错误。学生可见测试用于学习，独立核验使用另实例及保留条件；不能把隐藏答案打进公共 manifest。系统无法普遍证明程序正确，应明确有限测试和适用范围。

检查器输出 `met/not_met/needs_review`、条件 ID、反例/差异及工件绑定。编译错误、测试失败、超时、取消、环境故障分开；基础设施故障不得降低学生能力状态。执行成功与核验成功分开。禁止读取客户端提供的“正确答案”裁决。

### C03：证据、帮助、独立变体和恢复

至少绑定课程/目标/活动/标准版本、作品 ID/修订 ID/hash、任务实例/seed、输入、环境、工具运行、帮助快照、解释、结果、来源和时间。保存操作不等于达标；导入/同步的客户端报告不自动变成服务端证据。

每个目标将条件细分为有限客观核验、解释、独立应用等实际必要项。核验依据足够时才更新相应条件；开放论证须真实复核。不能把“解释不为空”直接判解释通过。答案后成功保留帮助标记，换题必须改变结构/约束或适用条件，不能只改标题。

作品提交后不可覆写，修改建立新修订；过程失败与旧成功都保留。异步返回核对账号 epoch、空间、修订和任务身份；退出/换账号后不得回写到另一空间。恢复含作品、环境配置、帮助与下一步；环境过期要新运行，不展示旧日志为新运行。

### C04：E07 审阅与异议回访

结构化提交证明、设计和解释；逐 criterion rubric；接单/退回/补证/复核历史；教师只看获授权内容。区分规则结果、模型建议、本人自述、授权教师意见和专业审校。

没有真实审阅者时不得显示“已安排教师”或自动签名。可以完成队列、权限、通知事件和测试账号端到端功能，但清楚标注该活动实际是否有审阅服务。AI 建议不能单独充当开放证明金标准。设计测试接受多个合理方案，不按字数或关键词计分。

### C05：E01/E03/E04/E05/E06 工具生命周期

统一 `prepare/run-or-step/inspect/check/snapshot/restore/cancel/cleanup` 能力描述；不适用方法显式声明。保留当前 Linux isolate 多语言 worker，固定依赖及实际 profile，不在业务 API 宿主执行学生代码。

- E03 SQL：独立实验 PG18，结果按集合/多重集/有序规则比较；每租约独立角色/数据，双连接屏障调度事务；禁止以 sleep 作为正确性依据。
- E04 Linux：真实受控子进程、管道、信号、同步、文件权限和重建；禁止用 Python 返回预置字符串替代真实系统调用。
- E05 网络：按已接受 ADR 的独立 VM 租约边界，内部 containerlab/Linux/FRR；浏览器终端、拓扑、配置、限定链路抓包、双向探针；网络外联关闭。不依赖 eNSP/Cisco，不宣称厂商 CLI 等价。具体首任务直接实施 `ACTIVITY_CONTRACT_EXAMPLES.md` 的 A—R—B 回程路由实验。
- E06 数据：沿用 `python313ml` 固定依赖环境，记录数据版本、划分、seed、预处理拟合范围、模型及指标。CPU 小数据完整支持，无需先建设 GPU。

所有工具测试取消、超时、重复请求、资源限制、进程/文件回收、断连和租约恢复。不能为了通过测试移除隔离或让学习任务访问宿主用户目录。

### C06：四职责、多模型和教学 Skill

按已有 `LEARNING_ASSIST_IMPLEMENTATION.md`、`MODEL_ROUTING_DESIGN.md`、`SKILL_DESIGN.md` 和 LangGraph 代码继续。四项职责保持为：规划与诊断、辅导、实践任务、核验。规划与诊断读取有效证据并安排后续；辅导引用当前工件与理论；实践任务提供与目标匹配的工件、条件和独立变体；核验调用受信工具并陈述局限。复盘由这些职责协作完成，不替换实践任务职责。按需课程/Skill设计不能凭空发布未核对知识。

按实际协议能力适配自定义模型，而非只在下拉框加名字。验证文本/结构化响应、流式、工具调用、超时、取消、不可用、限额和用户主动重试/切换。失败保留原请求，不自动跨供应商重试；用户换模型前按既定设计重新披露提供方与发送内容并确认。不同职责可选不同模型，必须记录本次实际模型版本/配置标识；后端保存密钥，导出要脱敏。

Skill 作为任务策略引用，包含输入输出、适用范围、工具权限、版本、试用和撤回。教师/学生自带 Skill 是不可信输入，不能抬高资料访问权限、改评分标准或运行宿主命令。自动生成 Skill 必须草稿→试用→校验→发布。此处“教学 Skill”与开发 AI 读取的本机 SKILL.md 是两个系统，不可混用。

模型凭据未配置时用明确标记的适配器夹具完成协议测试，不能把夹具写成真实模型联调通过。真实调用所需条件列入发布门，继续其他开发。

### C07：教师、自建课、资料与 RAG

允许名称/目标启动、自建大纲、上传 PPT/文档和可编辑的 AI 草案；发布前检查目标、关系、活动、标准和来源。上传解析需长度/类型/异常处理，原件与切片有所有者、课程、可见性和版本。

学生检索必须在服务端先按主体和可见范围过滤，返回文本、引用及缓存均执行同样权限；私有资料不得通过摘要、模型记忆、旧缓存、引用元数据或向量结果泄漏。测试撤销可见性、换课/换账号、教师私人资料和学生私人资料。教师看学生证据必须已有明确授权关系。

13 门默认课与自建课共用活动注册、工具、图谱和证据机制；未审校的 AI 草案保持标识。用户没有上传教材时仍可用默认完整内容。

### C08：五类先修桥接

按既定 BR-JAVA、BR-CPP、BR-PY、BR-MATH、BR-SHELL 建短任务包，每包都有必要说明、编辑/操作、真实检查和恢复。已有能力可直接核验跳过；不要求学生先安装完整 IDE。桥接不计入 13 课目标分母，也不能替代本课必要内容。

## 7. 13 门课的重点补齐方案

下面是相对既有局部活动的工程主线；完整逐模块要求见施工手册和原始课程方案，不得只做本节列出的综合项目。

### CS01 程序设计基础（C17，10 模块/30 目标）

复用现有多文件记录账本、恢复与缺陷活动。逐模块补完整编译/运行错误、类型和表达式前提、分支边界、循环不变量、函数递归、字符串终止、指针所有权、模块接口、失败后的文件一致性及缺陷检出测试。内存问题需受控诊断或作品审阅，无报错不等于安全；未定义行为不得指定一个固定正确输出。

综合项目：学生从可运行但有缺陷的记录程序迭代为可恢复的命令行工具。检查输入验证、动态容量、重复记录、部分写入、坏文件和恢复路径；替代实现接受不同内部结构。独立任务改变记录格式/异常注入，保存测试集能否真正杀死缺陷的证据。

### CS02 面向对象程序设计（Java21，8/24）
