# 个人真实学习测试方案

日期：2026 年 10 月 2 日。

状态：测试方案，尚未开始。项目发起人确认先由本人真实学习一门计算机专业课程；具体课程尚未确定，不写入虚构学习结果。

## 1 测试目的与范围

通过本人真实学习，发现目标协商、解释、实践、结果核验、学习状态、连续恢复和后续任务安排是否有用。测试围绕实际课程持续推进，不只验证页面操作或临时演示。

默认体验检验理论与实践是否在同一单元相互解释：自己遇到什么问题、做出什么尝试、系统因此解释什么原理、之后怎样修改和应用。记录讲解是否贴合当前作品，也检查课程知识是否连贯；不能只凭课程内容生成齐全或视频播放完成认为体验有效。

个人学习测试与产品逐门验收分别记录。所有声明支持的课程都要按 [课程矩阵](COURSE_SUPPORT.md) 和 [课程验证方案](COURSE_VALIDATION_PLAN.md) 检查，本方案负责本人持续学习一门课程的真实使用观察。本人不必先把每门课完整重学一遍，其他课程也不能免于验收。本人真实体验可以发现产品问题，不能直接证明学生群体的留存、提分或付费意愿。

## 2 开始前记录

| 项目 | 当前状态或填写内容 |
|---|---|
| 课程 | 尚未选定；首选建议数据结构，基础不足先补程序设计 |
| 可选参考资料 | 尚未提供；可不使用教材，使用时记录出处与版本 |
| 真实学习目标 | 选定课程后填写，例如想理解什么、完成什么 |
| 已有基础 | 本人声明与可检查的已有作品分别记录，未验证部分保持未知 |
| 课程章节与计划 | 从默认课程范围或可选资料提出，由本人修改确认；记录课程与路线版本 |
| 学习节奏 | 按真实时间安排，可随过程调整 |
| 环境与系统版本 | 原型可用后填写，不提前编造 |
| 学习身份与存储 | 未登录本地空间或账号空间，原型可用后记录关联与同步状态 |
| 实验依赖与数据 | 如课程需要，记录合法来源、版本和限制 |

选择课程时优先考虑本人确实愿意持续学习、系统有可检查教学依据且知识与实践能够相互核对的课程。外部教材和课程为可选对照，不要求先购买或上传教材。当前不指定某门课作为唯一产品场景，课程未确定也不阻碍通用流程和工具设计。

候选中文课程、教材与目标见 [默认方案建议](DECISION_RECOMMENDATIONS.md)。推荐并不代表本人已经选课；确认后才记录实际课程、资料版本和学习结果。

## 3 逐步开展

### 3.1 起步：先检查完整流程

先不提供教材，仅描述课程或学习意图，核对系统能否提出有依据、可修改的目标和路线并开展教学。选择相邻且有先修关系的知识单元，在具体问题中交替获得必要理论、亲自尝试、观察结果、解释和修改，再做阶段核验及后续安排。基础不足可先短说明／示范，不需先猜答案；检查同一工作区能否持续接续。若本人选用参考资料，再检查可选对齐；切换资料不丢失原有作品和进度。

先记录自己认为会什么，再通过作品与解释检查。系统提出目标与诊断时，观察是否理解了真实意图，是否引用了正确依据，是否让本人可以修改或拒绝。

先在未登录状态完成真实学习，刷新后核对本地作品和证据；随后登录本人账号承接记录，确认归属、同步和既有云端数据都正确。身份与同步机制见 [账号与数据设计](ACCOUNT_AND_DATA_DESIGN.md)。

### 3.2 持续学习：跨会话和章节推进

按真实节奏退出并回来，核对能否恢复当前任务、上次作品、已获得的帮助、待修问题和下一步。建议原型阶段至少覆盖三次独立会话，作为恢复机制的检查安排；不是学习效果已经验证的次数。

继续后续章节，记录哪些活动有用、哪些解释不清楚、哪些任务难度不合适。改变节奏或目标时，核对历史和影响是否清楚，路线是否依据新证据调整。

先完成若干单元只是阶段检查。本人应继续沿选定课程学习，按实际范围记录完成、暂停和未覆盖内容，不能把原型检查写成整门课程已经学完。

### 3.3 核验：检查帮助后的独立表现

同一个单元分别记录提示前尝试、获得的帮助、修改结果与独立变体表现。之后再做一个相关任务，观察是否仍能解释和应用；延迟间隔按实际学习安排记录，不预设结果。

编程课调用真实编译或执行工具，核对测试集、输出和错误状态。理论课保留推演、反例与评价标准。涉及数据库或数据实验时保存可复核结果及环境信息。不能因为 AI 说“掌握了”就结束核验。

按 [跨课程活动契约](LEARNING_LOOP_DESIGN.md) 核对选中活动的产物、核验边界和恢复对象。阅读或观看之后观察是否能预测、解释或应用；无法可靠评价的证明与设计保留待核验，并检查能否继续其他学习。外部提交和未观察的帮助不能自动当作已证明独立完成。

### 3.4 故障与纠正

主动检查编译错误、运行异常、超时、核验工具故障、评价解析失败、重复提交和中途退出。核对系统是否保留待核验、能否安全重试、有没有提前完成任务或重复更新状态。

对有问题的解释、测试用例、路线或诊断提交反馈，检查能否纠正并保留原判断与变化依据。故障检查使用独立测试任务，不破坏正在学习的作品与记录。

用专用测试数据检查重复导入、断网补传、附件失败、多标签页、A／B 账号切换、教师个人学习与授权撤销。本地“通过”字段被修改后不能成为可信核验；已有归属、未同步作品和迟到结果不能转入另一账号。

## 4 真实记录模板

每次实际学习后填写，当前不预填结果：

| 字段 | 记录内容 |
|---|---|
| 日期、系统版本、会话 | 实际信息 |
| 课程、单元、任务和版本 | 实际学习范围 |
| 活动契约、环境与核验方式 | 活动类型、产物要求、标准与支持边界 |
| 本次目标 | 已确认的目标与完成依据 |
| 提示前作品或解释 | 原始尝试与引用位置 |
| 提供的帮助 | 提示、示例或答案程度 |
| 理论与实际现象 | 本次概念／原理、自己的问题或结果、系统解释的依据；理论是否回扣活动 |
| 修改后结果 | 实际作品变化 |
| 教学调整与阻碍 | 本次表现如何改变支持；是否强制猜测、连续讲授、重复测评、理论断裂或切换丢失上下文 |
| 工具核验 | 运行环境、测试或标准版本、输出与状态 |
| 独立或延迟任务 | 实际条件与表现，未进行则标未核验 |
| 恢复与下一步 | 返回后是否接续正确、建议是否合适 |
| 本地关联与同步 | 空间归属、已同步及待传范围、冲突或失败 |
| 未决项与恢复限制 | 尚不能判断的部分、丢失状态、复核或重新执行要求 |
| 困惑与产品问题 | 具体触发过程及影响 |
| 改动与复查 | 修复版本及真实复查结果 |

个人作品、聊天、运行输出和学习记录在未登录时仅本地保存；登录关联后可同步到本人空间。Git 只保存测试方案、经整理的产品问题与不含个人资料的验收记录；不自动上传教材、私有作品或全部聊天记录。

## 5 阶段判断

- 能否独立开始并理解、修改目标。
- 帮助是否解决实际困难，是否保留本人继续思考和操作的机会。
- 理论、尝试与反馈是否在同一问题中接续，自己能否说明原理和适用条件；是否只学会照步骤操作。
- 能否自由试验和查阅理论，阶段核验是否适时，课程先修和重要概念是否连贯。
- 核验是否有真实依据，错误与工具故障是否分开。
- 本人是否能够独立处理类似或新的任务。
- 离开后是否愿意并能够回来继续，系统能否接续到正确位置。
- 本人课程中的教学与实践活动是否实际可用；其他课程验收另按课程矩阵记录，不以本次体验代替。

结论限定为“本人、这些任务、这些环境中的实际结果”。本人熟悉系统设计带来的偏差也应记入结论，后续推广前再根据需要开展其他用户验证。

课程尚未选定、环境未实现或任务未核验时，继续标记待确定或待验收，不用估计数字填补空缺。
