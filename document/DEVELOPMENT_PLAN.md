# 第一阶段开发计划

版本：v0.5

状态：阶段计划草案；没有团队规模／日历工期估算，不虚构交付日期。第一阶段包含 CS01–CS13 全量课程内容和支持验收，工程可分批实现，目标范围不得删减。

## 1 交付目标与执行方式

先固定用户流程、结构契约和完成门槛；再以端到端切片打通真实学习闭环，同时建立不依赖 13 门编号的课程、目标、活动与证据承载能力，并启动全部 13 门默认课程的蓝图和内容编制工作流；最后逐课补齐、验收并做发布演练。代表性单元可用于检验产品路径，但不能替代整门课程内容和验收。

完整第一阶段还包括 PRD 标注的 P0 运行能力、访客与账号数据规则、学生在 13 门之外自行建立私人课程并持续学习、教师授权与自建课程和资料导入、学生可见性及 RAG 权限、Skill 生命周期、多语言／SQL／基础网络实作、部署恢复。P1 不列入阶段门。13 门默认课程需逐门通过 CS01–CS13 覆盖报告与综合测试 RTM 才可宣称全量支持；个人课程不能抵扣这一要求。

## 3 课程内容工作流

所有 CS01–CS13 从 D0 起并行登记课程负责人和教研／环境审阅需求；每门课程使用相同 [课程包规范](COURSE_CONTENT_SPEC.md) 编制和版本控制。按“范围与依据 → 完整章节／知识单元 → 唯一可检验目标 → 理论／活动 → 核验／人工复核 → 证据／恢复／下一步 → 教研审校 → 课程测试”完成。

每课程至少交付：完整声明范围／深度及排除项、章节和目标覆盖表、教材可选的默认教学内容与来源、核心／选修及先修、各目标的可观察标准、关联活动和产物、有效核验或人工复核路径、故障／求助和权限说明、课程版本差异与发布审阅。支持能力不足不得静默删掉目标。

CS03 栈样例用于早期检查 schema、workbench 和核验管线；它是一个待教研审阅的单元，不决定个人实测选课，也不作为 CS03 全课程验收。全量课程内容是第一阶段退出条件。

## 4 开发完成定义

- 用户可从空账号／访客进入，选课程目标、主动学习与实践、运行或提交活动、得到可解释核验、返回课程图谱并继续；教师路径受独立授权控制。
- 学生可在 13 门之外自行建立私人课程，确认可修改的个人范围，留下真实尝试、待核验证据和继续位置；个人范围与经审校整课的进度及交付状态分别展示。
- 列入本次发布的每个 P0 需求有代码／内容／配置责任人与 RTM 验证证据；失败场景和回归已执行，P1 未实现能力明确延期。
- 课程包只按状态发布；CS01–CS13 完整版本和报告均存在。
- 全部前端页面按 [前端设计与品质标准](FRONTEND_DESIGN_STANDARD.md) 完成八维自检、修正、回归和独立复核；发布版本无明显可提升之处，页面／状态／设备覆盖和复核记录可核对。
- 无未处理的跨用户数据、教师私有资料／切片、受限答案泄露、不安全执行或学习状态伪写入阻断缺陷；FR44–FR46 有创建、资料提供、撤回和问答权限测试证据。
- 部署、恢复、回滚及访客清理过程可按文档由另一人重做；配置和工具版本可定位。

负责人、工作量、日历依赖和资金需项目发起人与实际开发者根据原型复杂度共同估算。本文件只列顺序和出口；收到能力测量、课程审校时间与资源成本后再填时长，不填无依据的完成日期。

范围变更关联 FR、课程目标、接口／数据和测试变化；重大跨文档架构选型增加 ADR。隐私／答案／隔离、安全和课程完整性缺陷需在阶段门复核。细分任务表在阶段 D0 完成后据团队真实分工生成。
