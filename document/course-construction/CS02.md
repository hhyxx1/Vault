# CS02 面向对象程序设计建设方案

状态：本科核心建设范围已确认；尚未构成已审校课程。下列模块进入建设范围，编写中继续查漏和核对深度。

## 1 范围、先修与环境

- 先修与补充：CS01 函数、复合数据与测试；提供 Java 语法桥接单元。
- 环境：E01 Java21 多文件、E07 设计审阅。适配器契约见[执行方案](ACTIVITY_ENGINE_PLAN.md)。
- 综合产物：图书借阅与预约系统。
- 当前计划：8 个模块、24 个可观察目标。数量是本方案的工作分解，不是已验证的学科覆盖结论；审阅发现遗漏须补齐。
- 无教材入口直接使用经审阅默认包；上传教材或教师大纲只改变来源映射与可选路线，不成为开课前提。

## 2 模块、目标与实践清单

每行目标依次编号为该模块 O01/O02/O03。例如 M01 的第一项目标是 CS02-M01-O01。下列活动是模块主任务；编写时须将三个目标的必要条件分别映射到作品、解释或独立变体，未覆盖的目标必须追加子任务。

| 模块 | 三个计划目标（依次 O01–O03） | 主活动与学生动作 | 核验方式及必须检出的错误 |
| --- | --- | --- | --- |
| M01 对象与封装 | 区分对象和类；设计可见性；维持构造与状态不变量 | 实现不可出现负库存的图书对象 | 构造及状态变更测试；反例为公开字段绕过约束 |
| M02 组合与职责 | 分配对象职责；表达组合关系；隔离存储和业务接口 | 拆解过度集中的借阅管理类 | 接口行为和依赖图审阅；类变多不自动代表设计更好 |
| M03 继承与多态 | 实现接口调用；判断替换是否保持契约；比较组合和继承 | 扩展借阅政策并暴露错误覆盖方法 | 经父类型运行行为测试；反例为子类破坏前置条件 |
| M04 泛型与集合 | 使用类型安全容器；选择集合语义；实现相等与哈希契约 | 维护去重索引和排序列表 | 重复对象、哈希冲突和顺序测试；不按类名判定 |
| M05 异常与资源 | 定义异常传播边界；保证失败后对象状态；关闭文件及外部资源 | 向持久化操作注入异常 | 资源与一致性断言；反例为 catch 后静默成功 |
| M06 对象关系与模式 | 表达关联及生命周期；应用策略或观察者解决实际变化；解释模式取舍 | 增加通知方式而保持核心行为 | 替代实现及设计说明；不靠出现模式术语评分 |
| M07 持久化与测试 | 转换对象与记录；设计可替换依赖；编写单元及集成测试 | 加载不完整记录并测试存储替身 | 模式兼容与真实文件往返；模拟通过不等于集成通过 |
| M08 综合演进 | 分析变更影响；重构并保持行为；复核设计约束 | 连续两轮扩展借阅项目 | 回归、对象图及评审；硬编码新角色是错误样例 |

## 4 综合任务的完整闭环

题目：交付“图书借阅与预约系统”。从可修改的初始工件开始，学生先解释关键假设、预测一次结果，再实际操作。

1. 规划：选择两个相邻模块，明确本次产物和必要条件；已有基础可直接提交作品核验。
2. 尝试：保存作品快照并运行对应工具或提交推演；出错后展示实际差异，链接到对应理论，而非直接代写正确作品。
3. 修正：学生修改并解释原因，再执行；保存失败与成功历史、帮助及答案使用。
4. 独立变体：改变“新增一种借阅政策、失败回滚和并发限制说明”；按适用条件设计保留任务，不能复制已揭示答案后就判独立达标。
5. 恢复：退出后恢复作品、活动版本、帮助和下一步；失效环境须重建并重新取证。
6. 汇总：每个必要条件分别反馈；开放解释交真实审阅流程，工具失败保留未核验。图谱只更新实际适用目标。

综合任务验收须列模块覆盖表；本任务未覆盖的模块仍需逐行主活动验收，不能凭综合任务成功宣布全课通过。

## 5 内容、来源与审校任务

按本课每个 Mnn 建立 SCOPE/THEORY/ACTIVITY/CHECK/VARIANT/GRAPH/REVIEW 七项任务，执行[任务分解](DELIVERY_PLAN.md)。每个目标至少提供必要概念、可追溯说明、正确示例、误区反例、实践、标准、提示和独立变体。

来源工作由内容作者先登记候选公开大学大纲、合法教材的章节定位和工具官方规范；学科审阅者核对覆盖与正确性。未实际查阅的页码和来源不能预填为已核对。CS2023 知识领域用于查漏，不直接当本课教材。公开课程文本采用原创整理或许可允许的材料，私人教材原件不提交 Git。
