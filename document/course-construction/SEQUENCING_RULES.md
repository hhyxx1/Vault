# 从课程模块到可学习单元

日期：2026-10-09。范围、语言和暂无专业审校的处理已由用户确认，见[确认记录](CONFIRMED_DECISIONS.md)。本轮交付是编排，不是发布课程正文。

## 1 本轮编排及下一层交付

13 份 [sequences](sequences/CS01.md) 编排共覆盖原计划 122 个模块、366 个目标，每模块给出不同的初始工件和变体条件。机器可读分配表为 [MODULE_SEQUENCE.csv](MODULE_SEQUENCE.csv)。A/B/C 是三个目标的编写入口，不是强制每模块只有三课时，也不是已经完成 366 份教案。

模块中的目标可能复合。例如 CS03-M04 同时涉及串匹配、稀疏矩阵、广义表，必须拆成多个知识单元及活动；不能靠一题 KMP 让整个模块通过。作者先写目标的必要条件，再按可完成的作品拆单元。超出一轮可理解范围就增加单元，不裁掉已确认核心内容。

每单元须交付：

| 工件 | 具体内容 | 完成判据 |
| --- | --- | --- |
| manifest | 稳定目标 ID、计划 ID、版本、核心范围、单元顺序、环境及来源引用 | 所有引用可解析；与既有目标有迁移决定 |
| starter | 可编辑的代码/数据/电路/关系/拓扑/证明骨架 | 空白基础学生可启动，错误版本可复现 |
| theory | 开展本轮操作需要的定义、前提、示例与反例 | 关键主张逐条核对；无需另购教材才能理解 |
| rubric | 每个目标的必要条件、证据类型、判定方法及未知处理 | 输出、过程、解释、迁移分别记录，不混为总分 |
| fixtures | 正确、替代正确、故意错误、边界及环境失败案例 | 每个期望有独立依据，检查器实际检出错误 |
| variant | 新输入/结构/约束及其检查条件 | 不依赖已揭示参考答案；重新收集独立证据 |
| source-claims | 主张、实际读过的出处、版本、许可、交叉核对和争议 | 无未解决知识争议；不以入口链接代替正文定位 |
| graph-review | 主归属、关联目标、关系理由、来源和审查结果 | 无虚构先修、悬空引用或重复统计 |

## 2 学生每次实际经历的步骤

1. 进入目标，看到要做成什么、当前已有证据、需要的先修能力和可用环境。首次可先做小尝试定位基础，不强制问卷或整课预考。
2. 对初始工件预测结果并实际尝试；完全陌生时可先展开概念和完整示例，不把“先猜错”做成强制关卡。
3. 系统展示真实输出或推演差异，链接到刚好需要的理论。辅导 Agent 基于当前工件、结果和可见来源提示，不伪造执行。
4. 学生修改工件，解释修改理由后再运行；前后作品及帮助记录持续保留。
5. 对已满足的条件反馈证据；解释或一般证明没有可靠判定时明确待复核。学生可继续后续学习，不因缺少审阅者永久锁住整课。
6. 换条件独立尝试；自学可主动看答案，但看过答案的同一题不能直接产生独立达标证据。教师任务沿用教师开放规则。
7. 保存下一步、作品和版本；刷新、换设备登录同步或环境租约重建后能继续。课程图谱只更新本次真正覆盖的条件。

时间安排按实际试学调整，不先捏造课时和完成率。第一轮记录任务用时、卡点、求助及恢复失败，但不能将作者走查当作真实学生学习效果研究。

## 3 推荐顺序与先修不是同一件事

各课模块默认 M01→末模块是课程编写和推荐阅读顺序；学生可以先诊断、跳转或走项目路线。图谱中的严格先修只记录完成某目标必不可少的能力，不把目录顺序转成整条锁链。

| 课程 | 需要重点拆分的内容 | 组合检查点 |
| --- | --- | --- |
| CS01 | 递归与作用域、数组与字符串、分配与所有权分别练习 | 分支计费→数组统计→多文件持久化记录器 |
| CS02 | 泛型/集合/相等哈希，异常边界/资源关闭分别检查 | 对象约束→政策与通知扩展→兼容持久化 |
| CS03 | KMP/稀疏矩阵/广义表；BST/平衡树/B/B+ 树；内部/外部排序 | 可替换容器→树索引→图导航与受限内存排序 |
| CS04 | MST/最短路/网络流；随机/摊还；归约/近似分别建立条件 | 正确性与反例→范式比较→受约束任务分配 |
| CS05 | 群/环/域，布尔代数/格，Euler/Hamilton/平面/着色分别拆单元 | 规则表达→证明与计数→离散模型及可达性 |
| CS06 | 定点/浮点；组合/时序；缓存/地址转换分别声明模型 | 编码和电路→教学处理器→访存及设备协同 |
| CS07 | 进程/线程，安全性/活性，真实文件/磁盘模拟分别取证 | 作业调度→同步与资源→故障观察与恢复 |
| CS08 | IPv4/IPv6，静态/动态路由，TCP/UDP，DNS/HTTP/TLS 分别实作 | 链路与子网→路由故障→端到端服务排障 |
| CS09 | 代数/SQL 多重集，范式/无损/保持依赖，日志模型/真实恢复分开 | 查询与模式→索引及事务→迁移和恢复 |
| CS10 | 可运行契约与开放设计评审分开，不把模板填空当工程 | 需求与模型→实现和质量→交付后需求变更 |
| CS11 | LL/LR 分别练；语言语义/宿主行为分开；局部/全局优化分开 | token/AST→类型/IR→优化与端到端编译 |
| CS12 | 对抗/局部搜索；逻辑/概率；规划/学习任务分开 | 状态与搜索→约束和推理→预算内规划与失效分析 |
| CS13 | 分类/回归；选择超参数/最终测试；聚类/降维分别检查 | 无泄漏基线→受控模型比较→可重跑预测交付 |

跨课先修先指向桥接能力，见[桥接包](DELIVERY_PLAN.md#6-先修桥接不能只留一个链接)。缺某项数学或语言能力时提供可实践补充；不要求为了学习 AI 先修完其余十二课。四项 Agent 职责保持规划与诊断、辅导、实践任务、核验；课程与 Skill 设计按需调用。模型意见不能跨过来源准入或可靠核验门。

## 4 建设执行顺序

1. 在全部 13 门保留完整目标台账，先逐模块落实来源正文与许可；缺源模块单独补源，不从核心分母删除。
2. 按共用环境制作首个真实单元和故意错误：代码、结构轨迹、逻辑、数字电路、系统、网络、SQL、工程项目、数据实验都要有代表。每种能力通过后再扩展使用它的模块。
3. 按各课顺序编写其余单元。初始工件、必要理论、检查器、变体和图谱关系同批交付，不先批量填一整课“概念节点”再无限期等待活动。
4. 每模块核查三项目标及拆出的条件，每课程做综合任务和遗漏回查；13 门分别记验收，不以 CS03 的成功替代其他课。
5. 无专业审校阶段按实际能力开放已核对内容并明确待复核条件；整课完整仍按 Q0–Q5 报告。

## 5 编写者拿到模块后的第一张任务卡

任务编号沿用 `B06-CSxx-Mnn-*`。领取后先交 `source-claims` 和 `rubric` 草表，明确每个条件用工具、有限模型还是开放审阅。随后交 starter、理论、fixtures、variant，实际执行后填结果，最后补 graph-review 和恢复测试。负责人与工时在真实领取时填写，不虚构人员或日程。

示例见[栈与括号匹配单元详案](UNIT_EXAMPLE_CS03_STACK.md)。这是编写深度样例，其他课程不得照抄它的核验方式；网络需要报文/配置状态，证明需要推理条件，设计需要取舍证据。
