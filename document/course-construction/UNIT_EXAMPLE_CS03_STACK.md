## 2 U01 的第一轮尝试

模型约定：容量 3，底到顶写数组；空 pop 返回 `EMPTY`，满 push 返回 `FULL`，失败不改变状态。错误值不作为可入栈整数，避免哨兵歧义。

| 步骤 | 操作 | 状态预期（底→顶） | 操作结果 |
| --- | --- | --- | --- |
| 1 | pop | [] | EMPTY |
| 2 | push 4 | [4] | OK |
| 3 | push 7 | [4,7] | OK |
| 4 | pop | [4] | 7 |
| 5 | push 9 | [4,9] | OK |
| 6 | push 2 | [4,9,2] | OK |
| 7 | push 5 | [4,9,2] | FULL |

学生先填第 4 步预测，再运行/提交轨迹；如果取出 4，辅导展示本次状态与后进先出定义，提示检查读取位置。学生修正后解释为什么剩余内容不变。另给成功弹出到空再弹出的新序列，不能直接复用上表认定独立完成。

## 3 U02 与 U03 不能被栈活动抵扣

循环队列约定容量 3，head 指向下次出队位置，tail 指向下次入队位置，显式 size 区分空满；初始三者为 0。执行入队 A/B/C、出队、入队 D 后，逻辑次序为 B/C/D。数组物理次序与逻辑次序分开展示。此处不混用“空出一格”实现的容量口径。

链式队列测试至少包括空队列、加入一个元素后删除、多个元素连续删除、重新入队。单元素删除后 head/tail 都要恢复空状态。检查返回值和结构约束；C++ 内存诊断作为额外证据，不把一次无报错当通用内存安全证明。

## 4 U04 理论插入点与独立检查

输入只包含 `()[]{}`，空串合法，采用从 0 开始的字符索引。基础接口返回是否正确匹配；扩展失配位置接口另立标准，不在基础判定中暗中加条件。

| 输入 | 预期 | 必须检测的条件 |
| --- | --- | --- |
| 空串 | true | 空输入处理 |
| ([{}]) | true | 正确嵌套 |
| ()[]{} | true | 多段并列 |
| ([)] | false | 括号数相同仍可能类型/嵌套错误 |
| )( | false | 闭括号出现时栈为空 |
| (() | false | 扫描结束仍有未闭合 |

在学生遇到 `([)]` 时补充“为什么计数不足以判断”的解释，让其修改配对逻辑并重跑。复杂度说明要求交代每字符操作次数及最大栈空间，不能用跑得快代替论证。参考答案展示后，对另一组序列核验；迁移条件还可要求报告第一个无法匹配的字符，未闭合则报告未闭合位置列表，须单独明确定义。

检查器先跑错误实现：只计总数、不检查括号类型、忽略结束时非空、空弹出仍继续。预期结果由明确语法模型核对；用同一份错误实现生成所有答案会使检查失去独立性。
