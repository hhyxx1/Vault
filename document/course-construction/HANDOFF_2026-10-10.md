## 3. 新增后端能力（这是本次的核心增量）

### 3.1 E02 引擎 —— `services/backend/src/vault_backend/course_checks/`

- `machines.py`：确定性教学状态机（纯函数、不依赖外部环境）。
  - `StackMachine(capacity)`：`push/pop`；空栈出栈返回 `status="underflow"`、满栈入栈返回 `"full"`，**失败操作绝不改变状态**。
  - `RingQueueMachine(capacity)`：显式 `head/tail/size`，下标取模回绕；`enqueue/dequeue`，空/满失败不改状态。物理布局与逻辑次序分开（不使用“空一格”口径）。
  - `Operation(kind, value)`；快照 `StackSnapshot(items,value,status)`、`QueueSnapshot(buffer,head,tail,size,logical,value,status)`；`machine.run(ops) -> list[Snapshot]`。
- `structured_trace.py`：
  - `TraceSpec`（frozen dataclass）：`activity_version / standard_version / checker_version / machine / state_fields / operations / criteria / capacity`，外加课程身份字段（见 3.3）；方法 `.expected()`（扁平正解快照）、`.expected_submission_steps()`（学生提交信封格式的正解，**服务端 only，禁止下发给学生端**）、`.context`。
  - `CriterionRule(id,title,steps,fields,check_value,check_status)`。
  - `verify_structured_trace(submission: dict, spec: TraceSpec) -> dict`：逐字段比对每一步 state/value/status；步数与 `spec.operations` 不一致抛 `ValueError`；输出 `rows[]`（逐行 issues）、`criteria[]`（`met/not_met/needs_review`）、`trace_correct`、`objective_state`、`summary` 等。**`explanation` 与 `independent_transfer` 永远 `needs_review`，`mastery_asserted` 永远 `False`，`provenance="server_deterministic_checker"`。**
  - `TRUSTED_TRACE_SPECS`、`get_trace_spec(activity_version)`（未知版本抛 `KeyError`）。模块导入时断言每个受信 spec 身份字段完整。
- 已注册的受信活动（操作序列以 `get_trace_spec(...).operations` 为唯一真相，勿手抄）：
  - `CS03-STACK-U01-TRACE@0.1.0`：standard `stack-bounds-trace-v1`，checker `stack-trace-checker@0.2.0`，栈容量 3，`state_fields=("items",)`；条件 `stack.order`（第 2–6 步）、`stack.bounds`（第 1、7 步）。题面操作序列：`pop, push4, push7, pop, push9, push2, push5`。
  - `CS03-QUEUE-U02-TRACE@0.1.0`：standard `ring-queue-trace-v1`，checker `ring-queue-checker@0.1.0`，循环队列容量 3，`state_fields=("buffer","head","tail","size")`；条件 `queue.fifo`、`queue.wrap`（回绕）、`queue.bounds`（空/满）。
- 测试 `tests/test_structured_trace.py`（20 个）：硬编码正解轨迹（独立于机器输出，专门防“自测自证”）+ 针对硬编码答案、漏判 underflow/full、只交最终状态、回绕布局错、LIFO/FIFO 混淆等反例。该测试曾独立抓出两个真实 bug 并已修复（栈 `pop` 快照在弹出前求值；一个标签命名笔误）。

### 3.2 HTTP 接线

- `schemas.py`：新增 `StructuredTraceStep{state: dict, value: int|null, status: ok|underflow|full}` 与 `StructuredTraceSubmission`（`kind="verify_structured_trace"`、`course_code="CS03"`、`activity_version` 只能取受信枚举、`steps` 1–64、`explanation≤4000`、客户端 UUID）。**不含 `standard_version`——标准/检查器版本由后端按活动版本裁定，客户端无法谎报。**

- `api.py`：`POST /api/v1/guest-leases/{lease_id}/operations` 的请求体联合类型加入新模型（按 `kind` 判别）。
- `responses.py`：新增 `StructuredCriterion`（`id` 为通用字符串、含 `title`）与 `StructuredVerificationResult`；扩展租约能力枚举、操作 `kind` 枚举与 `result` 联合类型。
- 契约已重新生成：`packages/contracts/openapi.json`、`packages/contracts/api.generated.ts`（已含 `StructuredTraceSubmission/Step`、`StructuredVerificationResult`、`verify_structured_trace`）。
