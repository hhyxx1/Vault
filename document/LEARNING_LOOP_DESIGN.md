# 跨课程真实学习与证据闭环设计

日期：2026 年 10 月 2 日。

状态：产品设计方案，尚未实现与验收。本文补齐课程矩阵中的活动契约，不证明现有系统已支持全部课程、实验或自动评价。

## 1 统一学习流程，按活动适配证据

所有课程共用目标、课程单元、活动、尝试、帮助、证据与恢复机制；执行环境和核验规则按活动类型适配。课程名称不能决定全部核验方式：算法既有代码，也有证明；网络既有实操，也有协议推演；软件工程既有测试，也有开放设计。

这些流程无需先登录。访客的目标、作品、帮助、证据和恢复位置仅本地持久保存，在线工具临时处理后返回结果；登录可将未绑定空间关联并同步到本人账号。学生／教师资料、个人学习与教学数据、教师授权以及同步来源的规则见 [账号与数据设计](ACCOUNT_AND_DATA_DESIGN.md)。

真实学习要求学生完成实际的思考、制作或操作，留下可检查的表现。教学可以基于系统经核对的默认课程知识、活动和标准，也可以对齐学生可选提供的合规资料，不要求先上传教材。适合抽象原理的推演与仿真也是学习活动，但其证据不能扩展成真实硬件、内核或厂商设备的实验表现。

完整闭环不是“上传教材 → 讲解 → 出题 → AI 宣布掌握”。它需要目标对应的学生表现、适用核验依据、帮助归属、证据范围，以及据此继续学习的安排。不能保证每个任务均能全自动判断，更不能保证学生必然学会。

## 2 从学习目标到下一次学习

| 环节 | 学生与系统需要完成什么 | 留下什么 | 推进边界 |
|---|---|---|---|
| 目标与起点 | 确认短期目标、完成依据；用已有作品或短任务了解必要先修 | 目标版本、原始表现、自述与待验证项 | 学生自述和问卷不能直接变成已掌握 |
| 学习与探索 | 阅读、观看、讲解、举例、预测或试验；允许按需提问 | 材料位置、问题、学生预测或解释、已提供帮助 | 看完、停留时间和聊天次数只证明行为 |
| 实践与产物 | 根据目标推导、编码、配置、建模、设计或实验 | 真实作品与必要检查点，标注可采集与缺失部分 | 不要求录下所有键盘或桌面动作 |
| 核验与反馈 | 工具检查实际结果，按标准审阅；对失败项提示并重试 | 依据、实际结果、标准版本、反馈和作品差异 | 环境错误、核验错误、作品错误分开 |
| 理解与迁移 | 解释关键选择；在改变条件的新任务中尝试，记录帮助 | 解释、新变体结果、帮助范围及不确定项 | 原题在提示后通过不能直接当独立迁移 |
| 局部状态更新 | 把证据关联到具体目标，保存判断理由与争议 | 证据引用、适用条件、已核验及待核验项 | 不把局部表现转成全课程掌握率 |
| 继续与再检验 | 恢复到作品和待完成动作；补先修、继续章节或稍后再检验 | 恢复位置、下一步理由、学生选择、实际延迟表现 | 未进行的迁移或延迟任务保持待检验 |

一段阅读或观看可以是训练活动，不必每页都测评；一个学习单元必须有可检查的学生表现。反馈不仅给分，还需指出具体差异并把操作交回学生。系统不能用自己生成的回答补写学生尝试。

后续安排采用明确分支：证据支持当前目标时提供下一活动；暴露先修缺口时建议补充活动；核验失败时保留作品并修改重试；证据冲突时补充检查或复核。学生能够调整目标和顺序，未决判断不自动成为已通过，也不强制阻断全部课程学习。

第一阶段提供跨会话恢复和简单复习、延迟检验入口；自动优化长期复习调度仍是后续候选，不因本文把它变成已实现能力。

## 3 每个活动必须有一份契约

活动创建和发布时至少声明下列内容，供界面、Agent、执行器、检查器和恢复逻辑共同使用。这里定义信息要求，尚未决定数据库或 API。

| 内容 | 必须明确的事项 |
|---|---|
| 关联与版本 | 访客本地空间或账号归属，课程、单元、目标、活动、资料、环境及核验标准的版本 |
| 学习目的 | 训练或核验哪些能力，是否需要先修；哪些内容不在这次结论范围 |
| 学生动作 | 学生要阅读、预测、解释、制作或操作什么；何时等待学生输入 |
| 产物与过程 | 需要的作品、状态或检查点；采集范围、操作者、缺失与外部上传来源 |
| 环境能力 | 所需语言、数据、模拟或实验环境；不具备时可做的替代活动及限制 |
| 核验依据 | 自动规则、已核对测试、可复核推演、评价标准或人工复核；依据来源与适用边界 |
| 帮助归属 | 提示、示例、答案与代操作分别记录，关联具体尝试 |
| 理解与迁移 | 解释要求、不同条件的任务及帮助记录；后续延迟检验如何进入 |
| 恢复方式 | 保存什么，能重建什么；哪些瞬时状态或外部环境无法恢复 |
| 故障与纠正 | 工具异常、采集缺失、标准争议、重试和内容修订如何处理 |
| 下一步 | 各类结果对应的建议及理由，学生如何接受或调整 |

没有可靠核验依据时，可以保存和反馈作品，展示“待核验”；不得发布为已支持自动核验的活动。外部上传的报告、截图或录屏标明来源和可复核程度，不自动证明所有操作都由本人完成。

## 4 按产物与环境共享能力

| 活动能力 | 可服务的课程 | 环境与核验分工 |
|---|---|---|
| 文本、推导、图表及设计作品 | 所有课程的解释；离散数学、算法、软件工程等 | 编辑与提交保存作品；规则或审阅按任务标准判断，缺乏可靠依据时待核验 |
| 代码与多文件执行 | 程序设计、数据结构、算法、编译原理及部分系统课程 | 执行器返回真实输出；测试、轨迹与解释各自核验 |
| SQL 与数据库实验 | 数据库及部分项目活动 | 保存数据初始化、查询、会话与事务；比较结果、约束和实际执行状态 |
| 有限推演与仿真 | 逻辑、组成、调度、自动机、协议过程等 | 保存输入、假设、步骤与模型版本；核对有限范围的状态和不变量 |
| 数据与模型实验 | 人工智能、机器学习及相关数据活动 | 保存数据处理、依赖、运行参数与实际结果；核对指标计算和实验方法 |
| 网络实验 | 网络及相应系统活动 | 保存拓扑、配置、状态、报文和检查结果；专用方案见网络设计文档 |
| 持续项目与专用环境 | 软件工程、硬件、内核、长期服务等 | 按任务增配工作区或设备；未实现的环境明确限制，不用模拟输出填补 |

这些是能力划分，不要求全部采用独立服务或同一种技术。一个代码执行器可以复用，但 SQL 多会话事务、网络拓扑和硬件操作不能强塞进普通标准输入输出判题。

环境适配器只返回运行与采集事实；检查器判断任务条件；Agent 解释证据并提出教学建议；状态服务验证版本与条件后更新记录。对开放问题，多个 Agent 同意不能代替可靠审阅。

## 5 常见课程逐项闭环示例

以下是每个领域需要实现的代表性案例及核验方案，全部待实现、待验收，不代表全课程内容已覆盖。更换题面、网段或数据时，应确实改变需要应用的条件，不能只换名称。

| 领域 | 真实活动与环境 | 学生和工具留下的证据 | 核验依据与限制 | 迁移、继续与恢复 |
|---|---|---|---|---|
| CS01 程序设计 | 先预测循环结果，再实现输入处理并调试 | 预测、源码版本、输入输出、错误和提示 | 编译或解释执行、已核对测试、边界输入；运行成功不等于正确 | 新输入规则下独立实现；恢复源码和未修错误 |
| CS02 面向对象 | 制作多文件类模型，再修改一项业务规则 | 对象图、接口与源码差异、测试、设计说明 | 行为测试及设计标准；功能通过不证明职责划分合理 | 新需求下修改并解释影响；恢复文件与约束 |
| CS03 数据结构 | 预测操作后状态，实现树或队列并修复边界问题 | 手工轨迹、实现、检查点、测试与重试 | 操作序列、结构不变量、边界测试；动画播放不证明理解 | 改换应用约束；恢复操作序列、作品和待解释项 |
| CS04 算法 | 设计策略，提出证明或反例，再实现对照 | 推导、反例、源码、输入规模和实际结果 | 正确性测试加已核对推理标准；有限测试不证明普遍正确，耗时不等于复杂度证明 | 换约束辨别策略适用性；恢复论证和实验条件 |
| CS05 离散数学 | 用关系性质、命题或图构造完成推导和反例 | 逐步证明、假设、图或集合、修改记录 | 有限实例可用真值表或枚举；一般证明须核对推理，必要时人工复核 | 改变假设或构造反例；恢复推导及未决步骤 |
| CS06 组成原理 | 推演指令状态，或在明确模型中设计简单逻辑电路 | 电路或指令产物、输入、寄存器与存储状态、轨迹 | 真值表、参考状态及指定模型规则；仿真不证明实物时序、功耗或板级调试 | 更换输入或故障条件；保存模型和作品，实物实验需另配设备 |
| CS07 操作系统 | 推演调度并编写受控同步程序，分析不同交错 | 调度表、程序、选定交错、运行条件与日志 | 参考推演、约束、受控运行及错误交错；一次运行不能证明无竞争、无死锁 | 更换调度条件或交错；恢复源码和场景，重新生成运行态 |
| CS08 网络 | 配置跨网段通信，观察报文并排错 | 拓扑、配置差异、接口与路由状态、抓包和帮助 | 双向通信、指定路由和协议条件；厂商行为需对应环境 | 新网段或故障独立排查；重建配置并重新检查 |
| CS09 数据库 | 建模、查询、约束和明确安排的多会话事务 | 模式、初始数据版本、SQL、结果与事务事件 | 处理顺序、重复值、NULL、约束及实际事务；不同 DB 和隔离级别分开 | 新数据含反例或改变约束；重置并重放初始化，未完成事务按环境说明处理 |
| CS10 软件工程 | 把需求转换为接口、验收测试和小项目改动 | 需求、设计决策、源码版本、测试及需求对应关系 | 可执行验收与评价标准结合；不能自动保证设计最优、可维护或真实团队协作 | 变更需求并解释取舍；恢复项目产物，长期服务待工作区支持 |
| CS11 编译原理 | 按给定语言规则构造分析器，解释错误输入 | 文法或自动机、实现、token 或语法树、分析轨迹 | 已知输入输出、结构及文法约束；按声明规则允许合法替代树或等价实现，不强制比较唯一字符串 | 新构造或歧义情境；恢复文法、测试和源码 |
| CS12 人工智能 | 对小问题建模，预测并运行搜索或受限推理 | 状态与目标定义、搜索轨迹、程序、约束和解释 | 实际解的有效性及指定策略规则；最优性结论限定前提和范围 | 改变状态空间或启发式；恢复问题定义和运行条件 |
| CS13 机器学习 | 从数据划分、基线到训练、误差分析与新评估 | 数据来源与版本或内容标识、划分与预处理版本、依赖、随机配置、模型和实际指标 | 核对泄漏、指标计算、评估方法和实际重复结果；种子不保证所有环境逐位一致，不能仅以高分认定学会 | 新的已定义评估数据或方法比较；保存实验，受限数据注明引用与无法重建范围，GPU 和大型训练另配环境 |

自然语言证明、开放设计和实验解释可以先获得有依据的建议；没有可靠审阅依据时保持待核验。教师或内容维护者审核标准、处理争议，不成为学生自主学习的启动条件。未决任务允许继续学习或选择已经核对的替代任务；原活动仍不能显示核验通过。

## 6 状态和证据不能用一个完成按钮代替

分别保存以下维度，而不是把它们强制合成一条掌握等级：

- 活动进度：待学生动作、进行中、已提交、核验中、满足活动条件、需修改或待核验；暂停后可恢复。
- 执行状态：真实环境运行、编译错误、异常、超时或环境失败；无执行工具的活动注明不适用。
- 产物核验：哪些规则满足、不满足或无法核验，依据及适用范围。
- 学习证据：帮助范围、当前任务表现、解释结果、迁移和延迟表现；各项独立记录。

“独立完成”仅说明本系统已记录的帮助范围和活动条件，不能保证学生没有使用外部帮助，也不自动推断诚信或归因为本人全部原创。

提交和检查绑定作品、任务、标准和环境版本。修改作品后不复用旧通过结论；迟到结果保留在原尝试，重复提交和重试不重复推进。修订材料或标准时保留历史，并明确是否需要重新核验。

采集缺失、时间线不完整、环境异常、评分解析失败和争议分别显示。无法确认的部分保持未知；不能由模型补写实验输出、学生解释或通过结果。

本地导入和同步保留原来源，不把客户端声明的通过升级为平台可信核验。退出或切换账号不能改变记录归属；迟到结果写入原空间，不能进入之后登录者的学习档案。

## 7 多 Agent 如何服务闭环

- 规划与诊断角色把目标对应到活动和下一步，引用具体表现并提出候选原因，区分先修缺口、任务误解、工具问题与证据不足；不能把生成路线视为学习完成。
- 辅导角色按需解释、提示或示范，记录帮助后把动作交回学生。
- 实践任务角色提供与目标匹配的任务和变体，使用经核对的标准，生成的新规则待校核。
- 核验角色调工具或按标准审阅，指出不确定项；不能同时代做再宣布学生独立通过。

各角色共享同一任务和证据版本；默认建议四项职责按需协作，框架与运行边界见 [默认方案建议](DECISION_RECOMMENDATIONS.md)，具体实现待验收。教师的标准审核、复核意见和纠正同样关联版本与证据。

## 8 如何证明闭环已经实现

课程矩阵各领域都要有真实验收记录；每类活动至少验证：

1. 从经核对的默认课程或可选参考资料建立目标，完成实际教学、学习与学生尝试，产物不是系统伪造。
2. 参考产物与故意错误产物产生可解释的不同结果；开放问题记录审阅依据和无法确定项。
3. 提示后完成与在记录条件下独立完成能够区分；新条件和之后的任务产生自己的证据。
4. 修改作品、重复提交、迟到结果和标准修订不错误推进状态。
5. 访客从本地、账号从本人空间回到具体作品和待完成动作；服务重启或环境重建后说明无法恢复的状态，访客远程任务过期可重新执行。
6. 工具失败、证据缺失或争议不会变成学生做错或自动通过；未决审阅仍可继续其他学习。
7. 根据实际结果安排下一步，学生能理解理由、选择调整并继续相邻单元。

验收记录包含课程与单元、活动契约版本、环境能力、标准与测试校核、实际证据位置、通过与未覆盖项、故障和恢复结果、复核人及日期。私有作品不默认进入 Git。

验收证明对应活动流程可用；本人真实学习测试检查这种支持是否有用、能否持续推进。二者都不能提前保证学习效果或整门课程全部能力。
